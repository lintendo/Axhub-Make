# Make 0.6.20-beta.1 Corrective Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a verified client template 0.1.20 and Make 0.6.20-beta.1 from the complete product snapshot, then publish them when registry credentials permit.

**Architecture:** Sanitize the isolated product snapshot first, then port only the hardened release infrastructure from the beta.0 line. Reconcile the newer client and fixed-template feature in the product snapshot with the validated 0.1.19 archive contract, and bind the Make beta to that immutable 0.1.20 client release.

**Tech Stack:** pnpm 10, Node.js 20, TypeScript 5, Vitest 4, Vite 5, GitHub CLI, Gitee release API, npm registry.

**Spec:** `docs/superpowers/specs/2026-08-17-make-0.6.20-beta.1-corrective-release-design.md`

## Global Constraints

- Client template version is exactly `0.1.20`.
- Make version is exactly `0.6.20-beta.1`; npm tag is `beta`; npm `latest` remains `0.6.11`.
- `@axhub/acp` remains exactly `0.1.13`.
- Preserve all 0.1.19 Design Knowledge, SHA, dual-source, archive allowlist, and packaged CLI gates.
- Publish the five fixed files under root `templates/`; publish no old `src/resources/templates/**` path.
- Do not modify the original dirty worktree or overwrite immutable published versions.
- Do not perform HTML/browser validation; use source contracts, builds, CLI/API smoke checks, and archive inspection.
