# Make 0.6.20-beta.1 Corrective Release Design

## Background

`@axhub/make@0.6.20-beta.0` was assembled from the client-template release line instead of the active Make product line. The two lines have no merge base. The published beta therefore contains the validated client-template 0.1.19 search and Design Knowledge work, but omits current Make features such as fixed document-template settings and retains the obsolete start-guide panel.

The active Make worktree also contains a large uncommitted product state. A release must preserve that state without editing it in place, remove generated artifacts that do not belong in source control, and then integrate the release hardening that was developed on the beta.0 line.

## Release identities

- Client template: `0.1.20`
- Make test release: `0.6.20-beta.1`
- Make npm dist-tag: `beta`
- ACP dependency: `@axhub/acp@0.1.13`
- Make `latest` must remain `0.6.11`.

Published versions are immutable. Neither client 0.1.19 nor Make 0.6.20-beta.0 is overwritten.

## Source-of-truth strategy

The source of truth for product behavior is snapshot commit `bb5593cdc28f480427c32f790555a8ae012df1db`, created with a temporary Git index from every tracked modification and every non-ignored untracked file in the active product worktree. The original worktree remains untouched.

The snapshot is sanitized before release:

- Remove side-by-side generated `.js` files when a same-path `.ts` or `.tsx` source exists and the `.js` file was an untracked addition in the snapshot.
- Keep intentional JavaScript sources, release scripts, client scripts, and committed `vendor/**/dist` artifacts.
- Do not copy `node_modules`, `dist`, `.release`, `.local`, coverage output, or local Make state.

The beta.0 branch is not merged as a tree. Only the reviewed release-helper hardening and the already-validated client 0.1.19 contracts are ported into the product snapshot, then reconciled with newer product files.

## Client template 0.1.20 contract

Client 0.1.20 is an additive correction of 0.1.19. It must retain:

- local `search-design-system` in both `.agents` and `.claude` skill roots;
- 223 validated `DESIGN.md` files plus desktop and mobile indexes;
- hash-verified primary packages and pinned Gitee fallback packages;
- no local theme source, theme archives, `node_modules`, `dist`, test files, or alternate lockfiles;
- the validated release manifest, archive SHA-256, frozen GitHub/Gitee assets, and exact source commit binding.

It additionally publishes these five regular files:

- `templates/prd.md`
- `templates/prototype-spec.md`
- `templates/prototype-spec.html`
- `templates/prototype-review.md`
- `templates/ui-review.md`

The old `src/resources/templates/**` paths are not published. Normal project updates and explicit restore operations add only missing fixed-template files and never overwrite edited templates.

## Make 0.6.20-beta.1 contract

Make beta.1 uses the current product snapshot and must:

- remove the obsolete empty-state start guide headed `我们先从哪里开始呢?`, including its prompt composer and inline app launcher;
- retain the normal project content and creation flows outside that obsolete panel;
- expose the five fixed document templates in Settings > Project Settings;
- serve fixed template list/read/write/restore APIs by registered ID only;
- bind `DEFAULT_MAKE_CLIENT_TEMPLATE_VERSION` to `0.1.20`;
- package version `0.6.20-beta.1` and depend on `@axhub/acp@0.1.13`;
- preserve the beta.0 release safety gates: clean exact HEAD, prepared artifact hashes, frozen upload bytes, exact GitHub target, Gitee versioned-first verification, and post-publication verification.

## Verification gates

### Gate A: source baseline

- No generated `.js` twin is tracked beside its `.ts` or `.tsx` source in the sanitized snapshot.
- Root Vitest, server typecheck, client tests, client typecheck, and client build pass.
- Fixed-template API and Settings source tests pass.
- A regression test fails if the obsolete start-guide panel returns.

### Gate B: client archive

- Version is exactly `0.1.20`.
- The five fixed templates are regular files, not directories or symlinks.
- All 0.1.19 Design Knowledge inventory, byte identity, SHA, dual-source, install, build, and alias-CLI checks remain green.
- All forbidden entry counts remain zero.
- Prepared and latest manifests agree on version, source commit, URLs, ZIP SHA-256, and latest-manifest SHA-256.

### Gate C: Make package

- `pnpm pack --dry-run` and the release helper agree on package contents.
- The tarball excludes tests, local worktrees, caches, generated release artifacts, and client theme source.
- Installing the packed tarball in a temporary directory can run the published CLI and start the server without relying on the repository checkout.
- The running package reports `0.6.20-beta.1` and client template `0.1.20`.

### Gate D: publication

- Client 0.1.20 GitHub and Gitee assets are byte-identical to the prepared frozen assets.
- The npm `beta` tag points to `0.6.20-beta.1`; `latest` remains `0.6.11`.
- If registry authentication is unavailable, publication stops without mutation and the exact commands are handed to the user.

## Failure and rollback policy

- Any failed source, archive, package, or post-publication gate blocks the next publication step.
- The bad beta.0 version remains immutable but must not retain the `beta` tag once credentials are available.
- Client 0.1.19 remains available by its versioned tag; client `latest` moves only after both source archives verify.
- No force-push, destructive reset, or overwrite of the original dirty worktree is permitted.
