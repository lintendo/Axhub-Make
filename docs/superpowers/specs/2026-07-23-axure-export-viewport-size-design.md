# Axure 导出视窗尺寸同步设计

## 背景

“导出到 Axure”弹窗的“原型截图”模式同时维护两类尺寸：

- `imageConfig.width` / `imageConfig.height`：用户可编辑的截图视窗尺寸。
- `imageConfig.screenshotWidth` / `imageConfig.screenshotHeight`：截图运行时返回的完整页面图片尺寸。

当前截图请求能够从预览配置中解析设备、自定义视窗或分屏主视窗的实际尺寸，但弹窗输入框没有沿用同一结果。输入框只会在部分内容类型切换时按设备默认值更新，因而可能继续显示标题封面的初始值 `500×300`，或在自定义视窗变化后显示旧值。

## 目标

- “截图视窗”输入框始终表达截图布局使用的视窗宽高，不表达完整页面图片宽高。
- 进入截图模式、打开导出弹窗或预览视窗变化时，如果用户尚未手动修改导出尺寸，输入框与截图请求使用同一份当前预览视窗尺寸。
- 用户在导出弹窗中手动修改或交换宽高后，自动同步不覆盖用户输入。
- 完整页面截图可能超过视窗高度；运行时返回的完整图片尺寸只用于预览和最终封面边界，不回写“截图视窗”输入框。

## 非目标

- 不改变标题封面的默认 `500×300` 尺寸。
- 不改变截图运行时对完整页面高度的测量和导出逻辑。
- 不重构整个导出配置状态或偏好存储结构。
- 不增加旧版本数据兼容分支。

## 方案

### 单一视窗尺寸解析

在预览操作控制器中基于现有 `resolveCurrentPreviewScreenshotSize` 生成当前截图视窗尺寸。该值覆盖：

- 桌面、移动端和平板预设；
- 自定义预览宽高；
- 分屏模式的主视窗宽高；
- 无法解析时的设备默认回退值。

自动截图请求、弹窗输入框自动同步和刷新去重键都使用这一个解析结果，避免同一时刻出现两套视窗尺寸。

### 自动同步与用户覆盖

现有 `userSetDimensionsRef` 继续表示用户是否在本次导出上下文中手动指定了尺寸。

- 切换到“原型截图”、切换资源或进入新的自动同步上下文时，将其恢复为自动模式。
- 自动模式下，打开导出弹窗或当前预览视窗尺寸变化时，把解析后的视窗宽高写入 `imageConfig.width` / `imageConfig.height`，随后以同一尺寸请求截图。
- 用户修改任一尺寸或交换宽高后，标记为手动模式。后续截图继续使用输入框值，不因预览配置更新而覆盖。
- 自动写入只在宽高确实变化时更新状态，避免重复渲染和偏好存储写入。

### 截图结果处理

截图结果继续只更新：

- `rawScreenshotUrl`
- `screenshotWidth`
- `screenshotHeight`

不使用运行时返回的完整页面宽高更新 `imageConfig.width` / `imageConfig.height`。这样长页面的完整截图高度不会成为下一次截图的视窗高度，也不会让用户面对不可预期的比例。

### 刷新与异步边界

弹窗截图刷新键包含解析后的当前视窗宽高，而不是只包含设备默认尺寸。因此，自定义视窗和分屏主视窗发生变化时也会触发一次新的截图。

本次修复不扩大为截图请求队列重构。已有请求结果仍按当前消息链路处理；输入框与完整截图尺寸分离后，旧请求返回不会把完整页面高度写入视窗输入框。

## 数据流

1. 预览配置变化或导出弹窗以截图模式打开。
2. `resolveCurrentPreviewScreenshotSize` 解析当前预览视窗。
3. 若为自动模式，将该尺寸同步到 `imageConfig.width` / `imageConfig.height`。
4. 截图请求使用相同尺寸作为 `targetWidth` / `targetHeight`。
5. 运行时按该视窗布局并捕获完整页面。
6. 返回的完整图片宽高写入 `screenshotWidth` / `screenshotHeight`，仅供 SVG 预览和最终封面边界使用。

## 错误处理

- 无效或缺失的预览尺寸继续由现有规范化函数回退到有效设备尺寸。
- 截图失败时沿用现有清空截图内容和提示错误的行为，不回退或覆盖用户输入的视窗尺寸。
- 用户暂时输入空值时沿用现有输入处理；截图只在失焦或交换宽高后触发。

## 测试

先增加失败测试，再修改实现：

- 自动截图时，输入框状态与请求 payload 使用同一个当前预览视窗尺寸。
- 自定义预览尺寸变化会进入截图刷新键和依赖链路。
- 用户手动修改尺寸后，自动同步不会覆盖输入。
- 截图结果只更新完整图片尺寸字段，不把完整页面高度写回视窗宽高。
- 标题模式仍保持 `500×300`。

验证范围为 `@axhub/make` 对应的定向 Vitest 测试，并根据改动影响运行 TypeScript 检查。
