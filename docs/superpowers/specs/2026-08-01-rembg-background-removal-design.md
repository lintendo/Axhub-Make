# 截图还原 rembg 背景移除设计

## 目标

为 Make client 的 `screenshot-to-prototype` 技能增加可选的 `rembg` CLI 背景移除能力，在不增加项目运行时依赖、不负责用户环境安装配置的前提下，提高复杂背景裁图的透明素材质量，同时保留现有裁切、键色透明化、切片和图片生成兜底能力。

## 质量判断

`rembg` 与现有键色脚本只在“把不透明背景变成透明背景”这一阶段存在替代关系，不替代 bbox 裁切、透明组件切分或素材矩阵切分。

组合使用优于只使用现有脚本：

- 现有键色脚本知道准确背景色，处理纯色生成背景时速度快、结果确定，能够稳定保留主体内部结构。
- `rembg` 使用语义分割模型，适合自然背景、渐变、阴影、发丝、柔和轮廓和前景背景颜色接近的素材，能够处理单纯颜色阈值无法可靠判断的区域。
- 场景分流避免把所有素材都交给模型，减少模型对小图标、几何 Logo、应保留背景的内容图片或已正确透明素材造成误切。
- 每个输出仍需经过素材审计；模型结果不合格时回退，不因本机安装了 `rembg` 就降低现有稳定下限。

质量提升最大的场景包括商品主体、头像、插画和独立装饰物位于非纯色背景上。对于已知纯键色背景，现有脚本通常不弱于模型；对于本应保留环境的照片、页面内嵌截图和背景图，不应触发背景移除。

## 方案比较

### 方案 A：完全使用 rembg 替换键色脚本

流程最统一，但会让纯键色素材承担不必要的模型推理成本，也可能误伤细线、孔洞、阴影和与背景语义接近的主体区域。CLI 不存在时还会失去当前确定性方案，因此不采用。

### 方案 B：所有透明素材先 rembg，再回退键色脚本

能够体现固定高优先级，但没有利用已知键色这一强先验。对于生成得到的纯色背景，先跑模型会增加时间和首次模型下载风险，质量也未必更好，因此不采用。

### 方案 C：按背景类型选择透明化方法（采用）

先完成 bbox 裁切，再判断是否需要透明背景以及背景类型。自然或复杂背景优先尝试 `rembg`；已知纯键色背景继续使用键色脚本。两条路线都需要审计，失败后再进入图片生成兜底。

## 处理流程

1. 图片 AI 按 UI 职责判断元素是否应成为独立位图，以及最终是否需要透明背景。
2. 按 bbox 裁切，并保留足够安全边距，避免模型输入在主体边缘截断。
3. 裁图已有正确 alpha 时直接进入审计，不重复移除背景。
4. 裁图应保留自然环境、构图背景或页面内容时使用 `clean-crop`，不调用背景移除。
5. 裁图需要透明背景且背景连续纯净、键色已知时，使用 `probe-key-color.mjs` 和 `key-transparent-image.mjs`。
6. 裁图需要透明背景且背景自然、渐变或复杂时，探测 `rembg` CLI：
   - CLI 可用时，使用 `birefnet-general` 生成透明 PNG 候选。
   - CLI 不存在时返回跳过状态，不提示安装、不修改环境、不阻断流程。
   - CLI 执行失败、模型不可用或输出审计失败时记录原因并进入现有回退。
7. 对透明输出运行 `audit-assets.mjs`。通过后可作为 `rembg-cutout` 候选；未通过时不自动选中。
8. 本地透明化没有合格结果时，使用 `ui-image-generation` 生成 `generated-refined` 或 `generated-chroma` 候选。纯键色生成结果仍由本地键色脚本最终透明化。
9. 候选、审计结果和最终选择继续写入重建映射，并在 HTML 主规格中实际渲染对比。

## 技能与脚本边界

- 新增跨平台 Node 包装脚本，负责调用 `rembg`，不把 shell 探测命令写死为 macOS/Linux 专用语法。
- 包装脚本接收输入、输出和可选模型参数，默认模型为 `birefnet-general`。
- 找不到可执行文件时输出结构化 `skipped` 结果并以成功状态退出，便于技能继续执行回退路线。
- CLI 已找到但执行失败时输出结构化失败原因；不尝试 `pip`、`uv`、Homebrew、模型下载命令或环境变量配置。
- 技能文档明确 `rembg` 是可选增强，不将其写入项目 `package.json`、pnpm workspace 或应用运行时。
- `.agents` 与 `.claude` 两份技能文件和脚本保持完全一致。

## 映射与审计

- 重建映射新增 `rembg-cutout` 表示路线，与 `clean-crop`、`generated-refined` 和 `generated-chroma` 区分来源。
- `rembg-cutout` 候选保存输出素材路径、所用模型和审计状态；不需要图片生成 artifact id。
- 验证器接受新路线，并继续要求被选中候选具有通过或明确带警告接受的审计状态。
- 第一版沿用现有 alpha 通道、透明边界、空图和尺寸检查，不在本次引入新的图像相似度框架。
- 主规格透明棋盘格与实际页面背景合成预览仍是最终人工视觉判断依据，可发现白边、黑边、主体缺口和不应移除的环境内容。

## 本机安装

本机安装与仓库技能实现分离：

- 安装当前最新版 `rembg[cpu,cli]`，使用独立 Python 3.12 环境，避免依赖系统 Python 3.9。
- 工具环境放在外置存储器 `/Volumes/WORK`，只在 `~/.local/bin` 放置轻量启动入口。
- 通过启动入口设置 `U2NET_HOME`，把模型缓存放在 `/Volumes/WORK`，不占用系统盘模型空间。
- 预取完整的 `birefnet-general` 模型。该模型约 928 MiB，质量优先于约 214 MiB 的 `birefnet-general-lite`。
- macOS ARM 使用 ONNX Runtime CPU 后端；该能力只用于素材生产，不进入页面运行时，因此允许以推理时间换取更高的候选质量。

## 验证

- 先增加失败测试，证明技能当前没有 `rembg` 优先级、包装脚本和 `rembg-cutout` 路线。
- 测试 CLI 不存在时返回 `skipped` 且不创建输出，不阻断后续流程。
- 使用测试替身验证 CLI 可用时传入 `i -m birefnet-general <input> <output>`，并返回成功结果。
- 测试 CLI 失败和缺少输出时返回可诊断结果，不执行安装或配置命令。
- 测试 `.agents` 与 `.claude` 镜像一致，以及重建映射验证器接受 `rembg-cutout`。
- 运行截图还原技能契约、图像脚本和工作流测试。
- 本机使用真实 `rembg` 和 `birefnet-general` 处理小型样本，确认输出 PNG 具有透明通道，模型文件实际位于外置存储器。

## 非目标

- 不在技能中安装 `rembg`、Python、ONNX Runtime 或模型。
- 不在项目依赖中加入 Python 包或 Node 背景移除库。
- 不要求所有用户使用同一个模型缓存路径。
- 不让 `rembg` 处理所有裁图，也不替代 SVG、HTML/CSS 或现有切片脚本。
- 不为旧版本 `rembg` 增加多套兼容分支；CLI 不符合预期时按失败结果回退。
