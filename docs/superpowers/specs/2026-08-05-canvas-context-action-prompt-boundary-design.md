# Canvas Context Action Prompt Boundary Design

## Goal

将基于用户当前所见画布内容执行 AI 操作的场景统一命名为“画布上下文操作”，并让运行时提示词只负责选择技能、声明执行顺序和传递动态上下文。可复用的产物呈现、判断和文件操作规则由 `canvas-workspace` 技能集中维护。

## Scene Contract

当一次任务同时提供以下信息时，命中“画布上下文操作”：

- 指定的 `.excalidraw` 目标文件；
- 用户当前看到的画布截图；
- 可选的当前视图坐标和可见元素 ID。

该名称与触发入口无关，适用于按钮、快捷键及未来其他入口。内部 `canvas-viewport` 标识继续描述截图范围，不做无关迁移。

## Prompt Responsibility

`buildCanvasViewportAiPrompt` 只输出：

1. 任务名称“画布上下文操作”；
2. 显式使用 `$canvas-workspace` 技能，先按“产物分流”确定画布呈现方式，再按“画布上下文操作”处理当前画布；
3. 多元素产物必须放在同一个 Frame 内，并让所有相关元素归属该 Frame；
4. 目标画布文件；
5. 当前视图坐标和可见元素 ID；
6. 当前画布截图已作为附件提供。

提示词不再重复编辑、新增、澄清、工具选择、文件重读、标记清理或 Excalidraw JSON 完整性规则。

## Skill Responsibility

`canvas-workspace` 的 frontmatter 描述补充“目标画布文件 + 当前所见截图/视图信息”的命中条件。正文先执行 `## 产物分流`，再进入 `## 画布上下文操作`：

- 画布负责组织、预览和操作项目产物，不代替产物本身；
- 文档先形成 Markdown、HTML 等项目支持的正式文档资源，再以内嵌文档节点呈现；
- 原型先形成项目内可运行页面，再以内嵌预览节点呈现；
- 图片先形成可持久化资源，再以图片节点呈现；
- 流程图、关系图和对既有画布元素的修改，才直接使用普通 Excalidraw 元素；
- 多元素产物先创建一个唯一的 Frame，所有相关元素（包括文字、形状、连线和图片）都设置同一个 `frameId`，并在写入后检查子元素、边界和引用；
- 技能只约束画布呈现合同，不点名文档、原型或图片的生产技能。

正文继续使用 `## 画布上下文操作` 作为稳定章节名，并集中规定：

- 判断编辑、新增或不明确意图；
- 不明确时只询问必要问题；
- 直接修改指定画布文件，不调用 MCP 或画布桥接工具；
- 修改原结构、选择合理新增位置、按遮挡关系清理操作标记；
- 保持 Excalidraw JSON、元素 ID、版本字段和关系引用有效。

复杂元素字段和绑定修复细节继续放在 `references/canvas-read-write.md`，主技能只保留执行决策和引用入口。`.agents` 与 `.claude` 两份技能保持字节一致。

## Output Completion Rules

“画布上下文操作”中的澄清规则只表达必要性：当现有上下文无法可靠判断时，询问必要问题。

流程图和其他由多个相关元素组成的新产物先创建一个唯一的 Frame，再创建或整理相关元素。所有相关元素（包括文字、形状、连线和图片）都必须设置同一个 `frameId`，该 `frameId` 必须指向实际存在的 Frame；Frame 自身保持 `frameId: null`。Frame 的边界必须覆盖所有相关元素，并使用表达产物内容的名称；写入后不得留下没有 `frameId` 的相关元素。产物已有可见边框或视觉容器时，Frame 的边框和背景保持透明，不重复创建视觉外框。已有结构性引用的详细检查继续由现有读写参考维护。

较长任务可以渐进式写入，以减少用户等待感。具体的批次、占位方式和时长阈值由任务上下文决定；唯一固定门禁是每次写入都必须保持完整、可解析的 Excalidraw JSON，并保留其他有效字段。

## Verification

- 提示词测试验证稳定任务名、显式技能引用、“产物分流 -> 画布上下文操作”的顺序和动态上下文存在。
- 提示词测试验证详细执行规则不再重复出现。
- 技能测试验证场景由输入上下文命中，不再出现“画布底部 AI 按钮”等入口位置文案。
- 技能测试验证文档、原型和图片使用正式资源节点呈现，不用普通画布元素模拟长文档或 UI。
- 技能测试继续验证意图判断、必要提问、直接文件写入、标记清理、Frame 命名与无重复边框、渐进写入门禁和关系修复规则。
- 运行技能目录校验、镜像一致性测试和相关生产构建。
