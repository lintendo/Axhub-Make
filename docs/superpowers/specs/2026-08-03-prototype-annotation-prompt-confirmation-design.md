# 原型标注提示词二次确认设计

## 目标

精简“复制提示词给 AI”生成的原型标注提示词，删除与项目内 `prototype-annotation` 技能重复的技术要求，并在目标资源中提供项目根相对入口文件。

AI 收到提示词后不得立即修改文件。它必须先用一次性固定提问告知用户支持的生成能力，并等待用户回复后再执行。

## 提示词结构

提示词只保留当前任务特有的信息：

- 要求使用项目内 `prototype-annotation` 技能，并以技能作为标注格式、接入方式和验证要求的唯一技术来源。
- 提供当前原型名称和项目根相对入口文件，例如 `src/prototypes/beginner-guide/index.tsx`。
- 要求读取入口文件、已有规格、需求文档和相邻资料；信息不足时不得臆测。
- 要求执行前进行固定提问。
- 要求完成后简要说明生成范围和仍需产品确认的内容。

不再重复 `AnnotationViewer`、稳定 locator、`currentPageId`、目录节点、Markdown 接入和运行验证等技能已经覆盖的技术细节。

## 固定提问

AI 在读取必要上下文后、修改任何文件前，只提出一次简短问题：

> 我可以为当前原型生成页面、Markdown 文档和外部链接目录，并补充内容标注和状态标注。你可以直接告诉我具体需求，也可以回复“推荐生成”，由我根据当前原型和已有资料生成一份可继续调整的基础版。你希望采用哪种方式？

该问题只介绍能力和两种回复方式，不要求用户逐项选择页面、文档、链接或标注类型，也不再发起第二轮范围确认。AI 必须等待用户回复；用户选择“推荐生成”时，AI 直接根据已读取的原型和资料确定基础范围，不能把未回复视为默认授权。

## 路径处理

入口文件使用现有 `currentFilePath`，按 `/` 统一分隔符。若收到绝对路径，则结合 `projectPath` 转换为项目根相对路径；无法确认路径位于项目内时不输出机器绝对路径。

## 验证

- 单元测试确认提示词包含原型名称和项目根相对入口文件，不包含项目绝对路径。
- 单元测试确认提示词要求一次性固定提问、等待回复，并介绍目录内容、标注能力和“推荐生成基础版”选项。
- 单元测试确认提示词不要求逐项确认范围或标注类型。
- 单元测试确认与技能重复的具体技术指令已从提示词中删除。
- 运行 `quickEditPrompts` 定向 Vitest，并检查 diff 空白错误。
