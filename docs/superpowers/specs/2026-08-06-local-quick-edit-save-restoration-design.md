# 本地快速编辑保存恢复设计

## 状态

- 日期：2026-08-06
- 状态：设计已确认，等待书面规格复核
- 范围：官方 Make 客户端中的原型、主题快速编辑保存

## 背景与根因

Make 的 `DevTemplateBootstrap` 仍通过以下本地 Runtime API 保存 React 原型和主题的直接编辑结果：

- `POST /api/text-replace/count`
- `POST /api/text-replace/replace`
- `POST /api/hack-css/save`
- `POST /api/hack-css/clear`

仓库迁移时，旧 `virtualHtml` 插件及其中的保存 handler 被删除；新的
`clientPreviewPlugin` 继续负责本地预览和管理运行时注入，但没有重新实现这些接口。
当前运行实例中，上述文本计数和样式保存请求均稳定返回 404。因此编辑器能够记录
DOM 修改并显示确认框，却无法统计替换数量或把修改写回源码。

此外，当前顶部“更多”菜单保留“保存文本”和“保存样式”，但没有“清空强制样式”入口；
预览也没有加载 `hack.css`，即使恢复写文件接口，重新打开页面后仍不能看到已保存的强制样式。

## 目标

1. 恢复原型和主题的本地文本保存。
2. 恢复强制样式保存，并让重新加载后的预览应用已保存样式。
3. 补回“清空强制样式”入口和落盘能力。
4. 接口不可用或请求不合法时停止保存并给出明确错误，不再在无法计数时继续替换。
5. 所有写入严格限制在当前项目的 `src/prototypes/` 和 `src/themes/` 内。

## 非目标

- 不实现 React DOM 到 JSX 节点的精确源码定位或 AST 级编辑。
- 不改变 HTML 资源现有的 `/api/html-review/*` 精确保存协议。
- 不增加云端保存服务或 AI 检测。
- 不兼容已经移除的 `pages/`、`elements/`、`components/` 目录协议。
- 不修改历史 Git 版本快照。

## 方案

### Runtime 本地编辑 API

新增职责单一的客户端 Vite 插件模块，由 `clientPreviewPlugin.configureServer()` 在预览路由之前调用。
模块识别四个现有 API，解析有上限的 JSON 请求，并对目标资源路径执行统一校验。

允许的目标路径为：

```text
prototypes/<safe-segment>[/<safe-segment>...]
themes/<safe-segment>[/<safe-segment>...]
```

解析后的绝对目录必须仍位于对应的 `src/prototypes/` 或 `src/themes/` 根目录内。
不跟随符号链接进入目录外位置。

### 文本计数与替换

文本保存继续沿用当前 UI 的“原文到新文案”分组语义。Runtime 只递归扫描目标资源目录下的
`.js`、`.jsx`、`.ts`、`.tsx` 文件，并排除 `.spec`、`.local`、`node_modules`、`dist`、
隐藏目录和 `*.assets` 目录。

计数接口接受批量 `replacements`，返回每组数量和 `totalCount`。替换接口先完成全部请求和
文件校验，在内存中生成所有新内容，再通过同目录临时文件和 rename 写入发生变化的文件。
批量替换采用单遍匹配，避免某组替换后的结果被后续规则再次替换。

请求边界：

- 单次最多 200 组替换。
- 单个原文或新文案最多 10,000 个 Unicode 字符。
- JSON 请求体最多 2 MB。
- 空原文、重复原文对应不同新文案、空替换列表均拒绝。

### 强制样式

`/api/hack-css/save` 把带现有临时说明注释的内容原子写入目标资源目录的 `hack.css`，
大小上限为 256 KB。`/api/hack-css/clear` 只删除该文件；文件不存在时返回成功且
`changed: false`。

预览 HTML 在 `hack.css` 存在时，将其作为独立 stylesheet 放在正式 `style.css` 之后，
确保覆盖顺序稳定。样式保存或清空成功后，编辑器确认相应变更并刷新当前 iframe；重新请求
预览 HTML 后即可加载或移除 `hack.css`。

### 编辑器与菜单

`resolveHostResourceContextFromLocation()` 增加 `themes/` 路径识别，使主题快速编辑也能生成
正确的保存目标。文本计数失败时，编辑器显示“无法统计文本替换数量，未保存任何修改”并返回，
不再把 `totalCount` 静默降为 0 后继续确认。

顶部“更多 → 保存”增加“清空强制样式”，调用现有 `clear-style` action，不新增协议类型。

## 数据流

### 保存文本

1. Commentary 在浏览器内收集文本变更。
2. `DevTemplateBootstrap` 按原文和新文案分组。
3. iframe 请求同源 Runtime 的 `/api/text-replace/count`。
4. Runtime 校验资源路径并统计代码文件中的匹配数量。
5. 用户确认明确的实际替换数量。
6. iframe 请求 `/api/text-replace/replace`。
7. Runtime 批量生成并原子写入变化文件，Vite 更新预览。
8. 编辑器仅在成功响应后确认已保存文本状态。

### 保存与清空样式

1. 编辑器收集当前强制样式。
2. 用户确认保存或清空。
3. Runtime 原子写入或删除目标资源的 `hack.css`。
4. 编辑器确认样式状态并刷新 iframe。
5. 新预览在正式样式之后加载存在的 `hack.css`。

## 错误处理

- 目标路径非法、越界或资源不存在：400/404，保持编辑状态。
- 请求体、替换数或内容超限：413，保持编辑状态。
- 替换组冲突或格式错误：400，保持编辑状态。
- 文件读取或写入失败：500，不确认编辑器保存状态。
- 文本计数失败：不显示无法预估的继续保存确认框，不调用替换接口。
- `hack.css` 不存在时清空：幂等成功。

服务端错误不返回项目绝对路径或完整源文件内容。

## 测试策略

### 单元与 API 集成测试

- 文本批量计数返回正确的分组数量和总数。
- 批量替换不会级联，且只修改允许的代码文件。
- `.spec`、资源目录、依赖、生成物和符号链接不会被扫描或写入。
- 路径穿越、非法组、空原文和超限请求被拒绝。
- `hack.css` 保存、覆盖、清空和幂等清空正确。
- 预览 HTML 仅在文件存在时于正式样式之后加载 `hack.css`。
- 主题路径能生成正确的编辑资源上下文。
- 计数失败时不会继续调用替换接口。
- 菜单包含“清空强制样式”并发送 `clear-style`。

### 浏览器验收

在当前官方客户端原型中：

1. 修改一处文本并保存，确认源码和刷新后的页面均更新。
2. 调整一处样式并保存，确认生成 `hack.css` 且刷新后仍生效。
3. 清空强制样式，确认 `hack.css` 被删除且刷新后覆盖样式消失。
4. 确认控制台和网络请求中没有 404、未接入保存能力误报或未处理异常。

## 验收标准

- 原型和主题的三项保存动作都能在本地项目源码中产生预期结果。
- 保存成功提示只在实际落盘成功后出现。
- 文本保存确认框显示实际替换数量；计数失败时不允许继续。
- 强制样式在重新加载后仍生效，清空后不再生效。
- 所有路径与文件类型边界测试通过，目录外文件保持不变。
- 不依赖云服务或 AI。
