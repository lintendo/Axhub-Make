# 原型标注会话模式设计

## 背景

原型预览顶部工具栏当前同时提供“打开”“规格”“批注”等操作。需求标注的手动启用入口藏在批注运行时的“更多”菜单中，用户需要先理解“批注”和“需求标注”之间的关系，才能进入正确路径。

现有系统已经具备完整的需求标注数据模型、手动启用 API、`AnnotationViewer` 接入方式和原型标注技能。此次只调整入口与编辑交互，不改变标注数据存储、服务端格式或 AI 生成规则。

## 目标

- 移除原型预览顶部工具栏中的“打开”按钮。
- 在“批注”后提供独立的“标注”按钮。
- 未开启需求标注时，引导用户选择手动开启或复制提示词给 AI；关闭路径退出标注模式并返回上一级。
- 启用后以独立标注会话进入既有批注运行时，默认聚焦人工标注编辑。
- 在气泡卡片中提供“人工 / AI 生成”切换，隐藏与标注无关的样式和设计修改工具。
- 复用现有 AI 原型标注技能，使 Agent 基于当前原型、规格和相邻资料生成标注、目录与 Markdown 文档。

## 非目标

- 不改变 `AnnotationSourceDocument`、目录节点或 marker 的 wire format。
- 不替换现有手动启用 API，或改变它写入原型的方式。
- 不新建第二套元素选择、定位、保存或 AI 执行链路。
- 不自动执行 AI 生成；AI 路径只复制可交给用户选定 Agent 的提示词。
- 不改变普通批注会话和文档编辑模式的交互。

## 入口与开启流程

### 顶部工具栏

原型预览的顶部工具栏顺序调整为“规格、批注、标注、决策、评审……”。移除“打开”及其快捷入口；其他资源类型保留各自的打开行为。

“标注”仅在当前原型可进入批注时可用，加载中或当前资源不支持时沿用现有禁用语义。

普通批注仍使用现有“批注”按钮。需求标注不再在批注运行时的“更多”菜单中暴露“开启需求标注”，避免两个入口表达同一件事。

### 未开启需求标注

点击“标注”后先读取当前宿主工具栏状态：

1. 已开启：直接进入标注会话。
2. 未开启：打开阻断式选择对话框。

对话框不响应遮罩点击或 Escape，也不展示右上角关闭图标。它只提供三个明确结果：

- **手动开启**：调用既有 `/api/prototype-annotation/enable` 流程。请求中禁用重复操作；成功后刷新现有状态并立即进入标注会话；失败时留在对话框内显示错误，可重试或返回。
- **复制提示词给 AI**：生成并复制当前原型的标注任务提示词。复制成功后关闭对话框并停留在普通预览，不进入标注会话；复制失败时保留对话框并显示错误。
- **返回**：关闭对话框，退出本次标注意图，回到普通预览。它不改变需求标注启用状态。

## 标注会话

标注会话是批注运行时的特殊上下文，参考文档模式的做法，而不是新的编辑器。它复用 iframe 握手、元素选取、气泡锚定、Markdown 保存和退出行为。

宿主在启动批注运行时传入明确的会话类型 `annotation`。运行时据此保持下列约束：

- 进入会话后保持元素选择可用；每次选中元素，气泡卡片默认打开人工标注编辑器。
- 当前气泡顶部展示稳定尺寸的分段切换：**人工** 与 **AI 生成**。
- 人工是默认项，显示已有的需求标注 Markdown 编辑器和保存/删除操作。
- AI 生成项关闭人工标注编辑器，显示已有的 AI 需求输入与发送能力；切回人工时恢复原有标注草稿。
- 禁用样式编辑、设计调整工具、设计令牌编辑与其它会改变页面视觉的操作；不影响已有 AI 发送、标注读取和保存能力。
- 退出批注运行时或点击现有退出操作会清理标注会话状态，后续“批注”入口仍以普通批注模式打开。

人工与 AI 生成切换只影响当前气泡的显示与可用操作，不能清空未保存的标注 Markdown、普通批注草稿或选中元素。

## AI 提示词

复制操作复用 `prototype-annotation` 技能的既有技术约束，并补充当前项目上下文。生成的提示词要求 Agent：

1. 定位当前 `src/prototypes/<id>/` 原型及其页面代码。
2. 读取当前原型的规格、相邻需求资料、已有 `annotation-source.json` 和项目规范。
3. 在必要时接入或更新 `AnnotationViewer`，但不改变已有可用数据。
4. 使用稳定 locator 生成组件标注，并为多页面/多状态传递正确的 `currentPageId`。
5. 根据资料生成 `directory.nodes`、内联 Markdown 文档和需要的 route/link 节点。
6. 按技能中的客户端验证命令检查改动。

提示词构建与复制使用现有安全的剪贴板封装和反馈方式。它不包含用户机器绝对路径，也不泄露运行时凭据。

## 数据与状态边界

| 状态 | 所有者 | 说明 |
| --- | --- | --- |
| 需求标注是否已开启 | 现有宿主工具栏状态与启用 API | 不新增持久化字段。 |
| 当前会话类型 | Make 预览控制器 | 仅在批注运行时存活；退出时清除。 |
| 气泡的人工/AI 生成选择 | Commentary UI runtime | 仅影响当前气泡显示；草稿仍由既有共享状态保存。 |
| 标注内容、目录和 Markdown | 现有 `AnnotationSourceDocument` | 保持格式和读写链路不变。 |

## 测试

- 工具栏源码/组件测试：原型工具栏不再渲染“打开”；“标注”紧跟“批注”；批注运行时更多菜单不再包含需求标注启用项。
- 预览控制器测试：已启用时直接以 `annotation` 会话打开；手动启用成功后进入该会话；返回和复制路径不会进入该会话；失败不会丢失对话框状态。
- 提示词单元测试：包含当前原型上下文、规格与资料读取要求、标注技能约束、目录与 Markdown 要求，且不含绝对路径。
- Commentary 运行时测试：标注会话默认选择人工并打开标注编辑器；AI 生成切换隐藏编辑器但保留草稿；样式与设计调整操作不可见；普通批注不受影响。
- 运行相关 Make 与 Commentary 定向 Vitest 测试，并执行 Make 前端构建或类型检查以覆盖跨包接口。

## 验收标准

- 用户可从原型顶部工具栏直观看到“批注”和相邻的“标注”，不再看到该原型的“打开”按钮。
- 未开启时只能手动开启、复制提示词或显式返回；遮罩和 Escape 不会意外关闭选择框。
- 手动开启成功后，用户直接进入默认“人工”的标注编辑气泡。
- AI 生成模式没有样式编辑工具，且往返切换不会丢失人工标注草稿。
- 标注数据及 AI 所产出的目录、文档与 marker 继续使用当前格式和现有规则。
