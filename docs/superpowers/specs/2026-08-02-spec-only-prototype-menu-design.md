# Spec-only 原型菜单设计

## 背景

Make 会把原型目录中存在 `.spec/spec.html` 或 `.spec/spec.md`、但不存在可运行 `index.tsx` 的资源识别为 spec-only 原型。这类资源仍有真实本地目录和规格内容，但会标记 `previewDisabled: true`。

当前侧栏菜单把两个不同能力混在一起判断：

- “访问链接”只检查资源类型是不是原型，因此 spec-only 原型即使无法预览，仍会显示访问入口。
- 重命名、创建副本、复制路径、下载 ZIP、版本和协作、删除依赖 `filePath`，因此只有 `specFilePath` 的 spec-only 原型无法使用这些本地管理操作。

截图中的 `government-service-home` 正是这种情况：目录和规格文件存在，没有运行入口，菜单却只显示无效的“访问链接”。

## 目标

- spec-only 原型不显示“访问链接”。
- 只要能从原型元数据解析出真实本地目录，就显示并支持本地管理操作。
- 普通可运行原型、文档和设计资源的现有菜单行为保持不变。
- 删除继续使用现有引用检查、确认对话框和项目范围保护。

## 能力规则

菜单不再使用单一的“是否有 `filePath`”判断所有原型操作，而是拆为两类能力。

### 预览访问能力

原型只有同时满足以下条件时才显示“访问链接”：

- 当前资源属于原型。
- `previewDisabled !== true`。
- 能构建出非空的本地访问 URL。

局域网链接和二维码仍作为“访问链接”的子能力，沿用现有 URL 与密码判断。spec-only 原型不渲染整个访问链接子菜单，不展示禁用入口。

### 本地目录能力

原型本地目录按以下优先级解析：

1. 优先使用现有 `filePath`、`absoluteFilePath` 或 `path`，并去掉末尾的 `index.tsx` / `index.jsx` / `index.ts` / `index.js`。
2. 没有运行入口路径时，使用 `specFilePath`。若路径包含 `/.spec/`，取该目录之前的部分作为原型目录。
3. 无法得到非空目录时，视为不支持基于文件系统的操作。

路径解析需要兼容 `/` 和 `\` 分隔符，不猜测固定的 `src/prototypes` 根目录，以支持自定义资源写入目录。

## 菜单行为

能够解析本地目录的 spec-only 原型显示以下操作：

- 重命名
- 创建副本
- 复制路径
- 下载 ZIP
- 版本和协作
- 删除

这些操作复用普通原型的现有处理链路，只把路径来源从“必须有运行入口文件”调整为“必须能解析原型目录”。

“重命名”继续只修改原型显示名称，不重命名目录。“创建副本”和“下载 ZIP”以解析出的完整原型目录为目标，因此会包含 `.spec` 和资源文件。“删除”删除完整原型目录，并继续清理项目元数据与导航。

菜单分隔线只在其后存在可见操作时渲染，避免再次出现只有一条无效操作和空分隔线的菜单。

## 错误处理

- 路径解析失败时不显示依赖本地目录的操作；处理函数仍保留运行时防御检查和现有警告。
- 访问 URL 为空或 `previewDisabled: true` 时不显示访问入口，不用禁用项代替。
- 删除引用检查失败、用户取消、目标路径不存在或服务端拒绝时，沿用现有错误反馈，不改变资源选择状态。
- 不从 `item.name` 拼接删除路径，避免自定义资源目录和跨平台路径下误删。

## 非目标

- 不为 spec-only 原型自动创建 `index.tsx`，也不改变其预览状态。
- 不改变原型扫描、规格读取、项目元数据格式或服务端文件删除协议。
- 不为没有本地目录的远程或引用原型开放文件系统操作。
- 不调整文档、设计、数据表或模板菜单。

## 测试

- 为原型目录解析增加单元测试，覆盖运行入口路径、spec-only 路径、Windows 分隔符和无可用路径。
- 为 `ContentPanel` 菜单增加回归测试，确认 spec-only 原型隐藏“访问链接”，同时具备本地目录时显示重命名、创建副本、复制路径、下载 ZIP、版本和协作、删除。
- 保留普通原型访问链接和现有 LAN 分享测试，防止可运行原型回归。
- 运行相关 Vitest 定向测试和 Make Admin 构建或类型检查。

## 验收标准

- `government-service-home` 这类只有 `.spec` 的原型不再显示“访问链接”。
- 同一菜单可执行删除，并能看到其他基于本地目录的管理操作。
- 删除目标是该原型完整目录，引用检查和确认流程仍生效。
- 普通可运行原型继续显示访问链接，其他资源菜单没有行为变化。
