# 画布 Markdown 渲染统一设计

## 背景

资源文档详情页使用 `@ant-design/x-markdown` 渲染 Markdown。画布内的 `axhub-doc` 节点则在 `AxhubDocEmbed` 中使用独立的轻量解析器。后者只支持标题、段落、列表、引用、代码块和分割线，未实现 GFM 表格；表格源码因此被当作普通段落显示。

同一份文档在资源页与画布中应有一致的正文语义和阅读样式。画布不需要资源页的目录、批注、编辑或多文档管理能力。

## 决策

新增一套可复用的只读 Markdown 阅读器，作为资源详情页和画布预览唯一的正文渲染内核。

- 阅读器基于现有 `@ant-design/x-markdown` 和其 light theme，不新增 Markdown 解析依赖。
- 阅读器负责 Markdown 解析、正文排版、表格和代码块样式、相对图片地址解析，以及可选的链接/标题渲染扩展点。
- 资源页的 `MarkdownViewer` 保留文档切换、目录、批注、编辑和保存逻辑，只将预览正文委托给阅读器。
- 画布的 `AxhubDocEmbed` 保留文档 URL 提取、请求、刷新去重、加载态、失败态和滚动容器，只将获取到的正文委托给阅读器。
- 画布不挂载目录、批注运行时、编辑器或资源页标签栏。

## 组件边界

共享阅读器放在 `src/common/markdown/`，避免由画布组件依赖 `spec-template` 的页面级模块。

阅读器接受 Markdown 正文与当前文档 URL。资源页可提供现有的文档链接导航和标题锚点扩展；画布使用默认的只读链接行为。相对图片继续通过当前文档 URL 解析为受项目作用域约束的资源请求。

阅读器自身使用作用域 CSS，只定义正文内容所需的视觉规则。资源页继续控制页面宽度、外边距和目录布局；画布继续控制节点尺寸、内边距与滚动。表格在画布的有限宽度中应可水平滚动，而不能撑破画布节点。

## 数据流

```text
Markdown 文件 API
    -> 资源页 MarkdownViewer -> 共享只读阅读器
    -> 画布 AxhubDocEmbed   -> 共享只读阅读器
```

画布同时兼容现有节点存储的原始 Markdown API URL 和 `spec-template.html?url=...` 形式。API JSON 包装的 `content` 字段继续在画布边界解包后再交给阅读器。

## 非目标

- 不把资源页的目录、批注、编辑、保存、标签页或多文档切换嵌进画布。
- 不保留或继续扩展画布专用轻量 Markdown 解析器。
- 不修改画布节点的数据格式、资源文件格式或打开文档的跳转行为。

## 验收与验证

- CRM 示例文档中的所有 GFM 表格在资源页和画布中均呈现为带表头、单元格和边框的表格。
- 标题、段落、列表、引用、代码块、链接和图片在两处使用同一正文渲染规则。
- 画布内宽表格在节点内滚动，不越出节点边界，也不影响画布缩放和拖动。
- 文档刷新后画布重新请求并以共享阅读器呈现最新内容；加载和失败状态保持现有行为。
- 为共享阅读器的表格/图片解析和 `AxhubDocEmbed` 接入添加聚焦测试；运行相关 Vitest 测试与 Make admin 构建或类型检查。
