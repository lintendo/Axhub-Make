# 标注协作看板 PRD 示例

## 1. 背景与目标

本原型用于说明 Axhub Make 的标注能力如何把可运行原型、节点说明、状态控制和补充文档放在同一个评审入口里。它不是一份静态说明页，而是一个可以切换页面、点击标注、查看目录和阅读文档的演示项目。

目标是让评审者理解：原型即 PRD 负责承载界面和交互，标注负责补充边界、原因和决策；页面目录组织页面与外部链接，文档目录独立收纳 PRD。这样产品、设计、研发和后续 Agent 可以围绕同一份上下文工作，减少原型、PRD、截图和聊天记录之间的重复同步。

## 2. 功能范围

- 原型即 PRD：把页面、PRD、标注和补充文档放在同一个原型入口中。
- 内容标注：演示任意元素标注、Markdown 正文、多颜色分类、颜色筛选和同一节点多条标注。
- 状态标注：演示结果状态、列表状态和指标状态，评审者可以在标注面板中切换不同业务状态。
- 文档模式：分屏阅读完整 PRD，通过独立文档目录切换文章，并用正文锚点定位页面或元素。
- 页面目录：组织原型页面和外部设计来源；PRD 从文档目录独立阅读。
- 开启 PRD 和标注：从原型顶部入口同时开启，可选择人工开启或 AI 开启。
- 编辑 PRD 和标注：从顶部文档管理编辑 PRD，并通过 AI 或手动方式编辑页面标注。
- Agent 读取：说明开发 Agent 读取源码、标注内容、文档内容和截图，用于后续开发。

## 3. 不在本次范围

本演示不覆盖真实后端接口、用户权限系统、多人实时协作冲突处理和正式发布审批流。它聚焦标注运行时本身，以及目录如何承载围绕原型的产品说明。

## 4. Markdown 层级案例

### 4.1 目录链接

- [背景](#背景)
- [范围](#范围)
    - [页面范围](#页面范围)
    - [状态范围](#状态范围)
- [验收](#验收)

### 背景

用于确认 Markdown 链接目录在文章正文中是否按普通链接展示。

### 范围

目录项需要支持一级和二级缩进，方便长文档快速定位章节。

#### 页面范围

页面章节用于描述入口、页面切换和节点位置。

#### 状态范围

状态章节用于描述默认状态、可切换分支和边界说明。

### 验收

点击或查看目录时，链接文案、层级缩进和标题结构都应保持可读。

### 4.2 多级列表

1. 一级事项：评审入口
    1. 二级事项：页面切换
        - 三级事项：保留当前标注上下文
        - 三级事项：确认 hash route 可定位
    2. 二级事项：目录文档
        - 三级事项：展示 PRD 和验收清单
2. 一级事项：标注阅读
    - 二级事项：按颜色筛选
        - 三级事项：只看风险或待确认项
    - 二级事项：按节点查看
        - 三级事项：聚焦当前激活节点

### 4.3 文档与页面定位

文档正文同时承载三类定位入口：页内锚点只滚动当前文章，文档间相对链接在阅读器内切换文章，页面目标链接在跨页时先切换原型页面再恢复高亮。

- [定位本文档起点](#prd-overview-anchor)：返回文章顶部，保持当前文章不变。
- [查看角色 PRD](./prd-01-roles.md)：文档间相对链接，在文档目录内切换文章。
- [查看指标阅读](./prd-06-metrics.html)：对照三档转化率及其判断规则。
- [查看内容标注](#axhub-target:content-preview-node)：跨页面目标链接，切换到“内容标注”并定位节点。
- [查看状态结果](#axhub-target:state-result-card)：跨页面目标链接，切换到“状态标注”并定位节点。
