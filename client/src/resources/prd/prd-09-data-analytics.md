## 背景与问题

飞书企业管理后台通过“数据报表”集中展示企业员工活跃和消息、云文档、日历、邮箱、任务、视频会议、服务台等产品的使用情况，并为知识库和应用使用数据提供增值能力介绍入口。当前产品缺少一份可追溯的现状规格，用于说明各报表已经呈现的筛选维度、指标结构、页签和空态，以及区分可直接查看的报表与当前套餐未开放的数据能力。

本文基于 2026-08-14 对当前租户登录视角的页面采集，反推以下 11 个一级页面的现状：数据概览、成员活跃数据、消息、云文档、日历、邮箱、任务、视频会议、服务台、知识库和应用使用数据。结论只来自 `src-001` 的页面 045-055 结构化提取与同名桌面截图，并引用 `prd-02` 的组织对象和 `prd-04` 的应用对象作为上下文。

采集时组织规模较小，多数功能使用指标显示为零，视频会议和服务台的排行、趋势或明细区域呈现无数据状态；这些值仅代表采集时的租户状态。本文保留指标和筛选结构，不固化企业名称、人数、比率、日期区间或其他具体租户数值。知识库和应用使用数据当前均为增值介绍页，其介绍的分析能力不作为已开通、可执行或可验收的报表能力。

## 目标与成功标准

### 产品目标

1. 为管理员提供企业员工与各产品使用情况的统一数据入口，并通过数据概览快速查看关键指标结构。
2. 支持管理员在成员活跃及消息、云文档、日历、邮箱和任务报表中按当前可见维度查看趋势并进入导出入口。
3. 展示视频会议的会议、用量、设备和服务数据，以及服务台的使用趋势与排名入口，并对当前无数据状态给出明确反馈。
4. 明确知识库和应用使用数据在当前视角下为增值介绍状态，使介绍内容与已开通报表清晰区分。
5. 建立可追溯的验收边界，避免把未切换的二级页签、未执行的筛选和导出、未说明的统计口径或增值介绍能力写成已验证事实。

### 成功标准

1. 11 个页面均可从“数据报表”导航定位，并呈现本文列出的页面层级、筛选项、指标名称、状态和主要入口。
2. 数据概览保留员工及 7 类产品使用数据的指标分组；成员活跃及消息、云文档、日历、邮箱、任务保留各自的指标结构。
3. 视频会议和服务台能够呈现当前已观察的日期、维度、导出入口及无数据反馈，不要求补造有数据样例。
4. 知识库和应用使用数据明确显示增值介绍、帮助、升级或咨询入口，不把介绍中的指标、下钻、API 或导出能力作为当前套餐的执行验收。
5. 验收不依赖采集样本的企业名称、人数、比率、日期和指标值，也不要求筛选结果、详情页签或导出文件与未观察状态一致。

## 用户、角色与场景

| 用户/角色 | 触发场景 | 核心任务 | 当前证据边界 |
| --- | --- | --- | --- |
| 企业超级管理员 | 查看企业整体采用和产品使用情况 | 从数据概览查看员工与产品指标，并进入对应详情报表 | 当前采集账号可访问页面，但未验证各报表仅限超级管理员 |
| 具有数据报表权限的子管理员 | 按职责查看指定组织或产品数据 | 选择日期、组织或产品版本，查看趋势并使用导出入口 | 页面未展示独立角色名称，授权范围和无权限结果未采集 |
| 组织或人事管理相关管理员 | 跟踪成员激活与活跃情况 | 查看活跃、激活、人员变化和使用时长趋势 | 成员活跃详情页签未展开，成员级字段和隐私规则未观察 |
| 产品运营相关管理员 | 了解各协作产品的使用情况 | 查看消息、文档、日历、邮箱、任务、会议或服务台指标 | 指标定义、去重、时区和跨产品关联规则未说明 |
| 应用管理相关管理员 | 了解应用安装与使用能力 | 查看应用使用数据的当前版本状态和能力介绍 | 当前仅为增值介绍页，实际报表、部门下钻和 API 数据均未验证 |

主要场景包括：

1. 管理员进入数据概览，选择截至日期、组织和产品版本，查看员工与各产品的指标卡，并从“查看详情”进入相应报表；本文只确认入口存在。
2. 管理员进入成员活跃数据概览，选择日期范围、组织和产品版本，查看活跃、激活、人员变化及每日人均使用时长趋势。
3. 管理员分别查看消息、云文档、日历、邮箱和任务的使用指标，并从当前可见入口发起导出；本文不定义导出结果。
4. 管理员在视频会议概览中查看会议总量与日均数据、用户和地点排行、日/月用量、设备与客户端服务数据；当前多个区域为空。
5. 管理员在服务台“使用情况 / 趋势概览”中按日期、已启用服务台和用户部门筛选使用指标；当前趋势数据为空。
6. 管理员打开知识库或应用使用数据，查看增值能力说明、帮助和升级咨询入口，而不会把介绍页误认为已开通报表。

## 范围

### 本次包含

- 数据概览：截至日期、组织、产品版本筛选，导出与各分组查看详情入口；员工、消息、云文档、日历、邮箱、任务、视频会议和电话服务指标结构。
- 成员活跃数据：概览/成员活跃详情页签，日期范围、组织、产品版本筛选，导出入口，以及活跃、激活、总人数、新用户、新激活、离职和使用时长趋势指标。
- 消息、云文档、日历、邮箱和任务报表：日期范围、组织、产品版本筛选，导出入口及各页面当前可见指标结构。
- 视频会议：概览/数据报告页签，会议数据/电话服务/视频会议 AI 维度入口，日期范围，总量与日均指标，用户和地点排行，日/月用量、设备和客户端服务数据区，以及各处导出入口和当前空态。
- 服务台：使用情况/运营情况页签，趋势概览/服务台排名入口，日期、已启用服务台、用户部门筛选，导出入口，使用人数与工单指标及当前空态。
- 知识库：当前增值介绍页中的产品说明、帮助、升级/咨询入口、功能亮点、客户案例和套餐对比内容区。
- 应用使用数据：当前增值介绍页中的产品说明、帮助、升级/咨询入口、功能亮点、功能问答和套餐对比内容区。
- 当前可见的默认态、零值态、无数据态和版本受限态。

### 不在本次范围

- 成员活跃详情、视频会议数据报告、电话服务、视频会议 AI、服务台运营情况和服务台排名等未切换页签或维度的内部结构、字段和行为。
- 数据概览各“查看详情”的跳转结果与参数传递规则；虽有对应独立页面，本次未从入口实际触发并验证。
- 日期、组织、产品版本、服务台、用户部门、会议维度和设备系统版本筛选的完整枚举、默认规则、组合逻辑、重置行为、无结果和错误状态。
- 任何指标的业务定义、去重逻辑、分子分母、统计时区、数据更新周期、延迟、补数、历史回溯和跨产品数据一致性；页面未提供足够证据。
- 导出范围、字段、文件格式、命名、排序、权限、生成方式、下载结果、任务状态和失败处理；本次只确认导出入口。
- 有数据状态下的视频会议排行、地点、设备、客户端反馈和服务台趋势、排名、工单明细，以及任何下钻对象或详情字段。
- 知识库实际使用数据看板、知识库增长/访问/贡献报表，以及升级后的页面、数据和操作。
- 应用使用数据的总体数据、累计安装、可用人数、使用人数、分部门详情、应用列表导出和 API 数据获取；这些只出现在增值介绍文案中。
- 套餐名称、额度、价格、购买资格、升级结果及套餐对比内容的长期稳定性。
- 后端数据仓库、埋点、API Schema、指标计算、权限算法、导出实现及任何行业惯例补充。

## 用户故事

1. 作为企业管理员，我希望在数据概览中查看员工和主要产品的指标分组，从而快速判断需要深入查看的领域。
2. 作为组织或人事管理相关管理员，我希望按日期、组织和产品版本查看成员活跃趋势，从而了解人员激活与使用情况。
3. 作为产品运营相关管理员，我希望查看消息、云文档、日历、邮箱和任务的使用指标，从而了解各协作产品的采用情况。
4. 作为会议运营相关管理员，我希望查看会议总量、时长、参会、排行、设备和服务数据，从而掌握会议使用情况；没有业务数据时仍能识别页面结构和空态。
5. 作为服务台运营相关管理员，我希望按服务台和用户部门查看使用人数及工单趋势，从而了解服务台使用情况；当前没有数据时能获得明确反馈。
6. 作为有数据导出需求的管理员，我希望在报表中看到导出入口，从而继续发起数据获取；本文不承诺未观察的导出文件行为。
7. 作为企业管理员，我希望清楚识别知识库和应用使用数据当前属于增值介绍，从而选择查看帮助、升级或咨询。

## 能力与信息架构

```text
企业管理后台
└── 数据报表
    ├── 数据概览
    │   ├── 员工
    │   ├── 消息、云文档、日历、邮箱、任务
    │   └── 视频会议、电话服务
    ├── 成员活跃数据
    │   ├── 概览（当前）
    │   └── 成员活跃详情（仅确认页签）
    ├── 功能使用情况
        ├── 消息
        ├── 云文档
        ├── 日历
        ├── 邮箱
        ├── 任务
        ├── 视频会议
        │   ├── 概览（当前）
        │   ├── 数据报告（仅确认页签）
        │   └── 会议数据（当前）/ 电话服务 / 视频会议 AI
        ├── 服务台
        │   ├── 使用情况（当前）/ 运营情况
        │   └── 趋势概览（当前）/ 服务台排名
        └── 知识库（增值介绍页）
    └── 应用使用数据（增值介绍页）
```

数据概览用于跨模块汇总和进入详情；成员活跃及 5 类基础功能报表提供各自的趋势指标结构；视频会议与服务台具有更深的页签、维度和内容分区，但本次仅定义默认可见状态；知识库和应用使用数据当前不提供实际报表，只呈现增值能力说明。

## 数据模型

本节描述页面上对管理员有意义的业务对象和展示字段，不代表数据库、埋点或 API 设计。

| 业务对象 | 已观察字段/属性 | 对象关系与当前状态 |
| --- | --- | --- |
| 报表查询范围 | 截至日期或日期范围、组织、产品版本 | 数据概览使用单个截至日期；成员活跃及消息/文档/日历/邮箱/任务使用日期范围。组织与产品版本的枚举和作用机制未展开 |

| 云文档使用指标 | 云文档活跃人数、创建文件人数、创建文件数量、人均创建文件数量 | 数据概览和云文档报表均有相应结构；文件范围未说明 |
| 日历使用指标 | 日历活跃人数、创建日程人数、创建日程数、人均创建日程数 | 数据概览和日历报表均有相应结构；日程范围未说明 |
| 邮箱使用指标 | 概览：邮箱使用人数、总发件量、总收件量、人均发件数、人均收件数；邮箱报表：总发件量、总收件量、对外发件数、来自外部收件数、对内发件数、来自内部收件数 | 两个页面的字段结构不同；不据此推断包含或换算关系 |

| 视频会议分析区 | 前 10 位用户、前 10 个地点、日用量、月用量、会议设备类型、会议设备操作系统、客户端满意度、客户端反馈 | 当前多个区域无数据；有数据字段、排行规则和反馈内容未观察 |
| 电话服务概览指标 | 总通话数、总通话时长、总使用人数、人均通话时长、最大并发数 | 仅在数据概览可见相应指标结构；视频会议页内电话服务维度未切换 |
| 服务台使用指标 | 服务台累计使用人数、服务台使用人数、创建工单人数、创建工单数、人均创建工单数 | 当前趋势区域无数据；工单对象、状态和统计口径未观察 |
| 知识库数据能力介绍 | 访问、新增与互动情况；增长趋势、优质内容、部门与成员贡献等说明 | 当前为增值介绍，不存在已观察的实际报表对象 |
| 应用使用数据能力介绍 | 应用总体数据、累计安装数据、单个已安装应用的可用人数与使用人数、分部门详情等说明 | 当前为增值介绍；应用对象可参考 `prd-04`，实际统计对象和页面未观察 |

## 业务规则

| 规则 ID | 条件 | 可见动作/结果 | 限制与证据边界 |
| --- | --- | --- | --- |
| `DA-R01` | 管理员打开数据概览 | 页面展示最新数据截至日期、组织与产品版本条件、导出入口，以及员工和产品指标分组 | 采集样本的日期、组织名、版本和值均为动态数据，不固化为默认规则 |
| `DA-R02` | 管理员查看数据概览分组 | 员工、消息、云文档、日历、邮箱、任务、视频会议和电话服务分组均提供指标结构及“查看详情”入口 | 详情跳转、查询条件继承和返回行为未从入口触发验证 |
| `DA-R03` | 管理员打开成员活跃数据 | 默认展示“概览”，并可见“成员活跃详情”页签、日期范围、组织、产品版本、导出及 7 组趋势指标 | 详情页签未切换；曲线值不作为稳定产品规则 |
| `DA-R04` | 管理员打开消息、云文档、日历、邮箱或任务报表 | 页面提供最新数据截至日期、日期范围、组织、产品版本、导出和对应指标图表 | 筛选未执行，导出未触发，图表交互、悬浮值和统计口径未观察 |
| `DA-R05` | 管理员查看任务数据概览 | 数据概览页面显示任务数据开始提供时间的提示 | 该时间是页面可见说明；其之前的数据缺失、补录和跨时区规则未说明 |
| `DA-R06` | 管理员打开视频会议 | 默认位于“概览 / 会议数据”，展示日用量数据、日期范围、会议总量与日均指标，以及排行、用量、设备和服务分区 | 数据报告、电话服务和视频会议 AI 未进入；其内部结构不得据默认页推断 |

- 零值必须作为有效指标值显示；无数据区域必须有独立的空态反馈，不能把零值、无数据、加载中和错误状态混为同一表达。
- 知识库和应用使用数据的增值标识、升级入口与介绍内容在视觉层级上与可直接查看的报表页明确区分。

### 实现验收

- 按 `DA-AC01` 至 `DA-AC13` 在具备相同访问条件的桌面登录视角逐页核验可见结构、指标名称、状态和入口。
- 仅验证已观察的默认态、零值态、无数据态和增值介绍态；不以切换成员详情、会议数据报告/电话/AI、服务台运营/排名，执行筛选、下载导出或升级作为通过条件。
- 对组织、产品版本、日期、人员和所有统计值只验证字段及状态表达，不断言采集样本的具体名称、数值、曲线或日期区间必须复现。
- 导出入口只验证可见性和所属内容区，不验证点击后文件、任务、权限、成功提示或错误恢复。

### 回归风险

- 成员加入、激活、离职或组织调整会改变员工概览和成员活跃趋势，并可能改变组织筛选选项。
- 消息、文档、日历、邮箱、任务、会议和服务台产生新业务数据后，当前零值或无数据状态会消失，需要补充有数据图表、排行、明细和交互证据。
- 产品版本或套餐变化会改变产品版本筛选、知识库和应用使用数据的增值标识、升级入口、套餐对比及实际可用页面。
- 应用安装、停用或可用范围变化会影响应用使用数据；即使后续开通，也不能直接沿用 `prd-04` 的列表字段作为统计口径。
- 数据统计规则、刷新周期或历史补数变化会改变图表和导出结果；当前页面证据无法覆盖这些内部规则。
- 管理员权限变化会改变页面可达性、组织范围、详情可见性和导出权限。

## 风险与依赖

- **风险：统计口径不可见。** 页面只提供指标名称，没有足够证据说明去重、分子分母、时间边界、刷新和补数规则，不能据界面名称验证数值正确性。
- **风险：样本数据覆盖有限。** 当前组织规模小且多数产品指标为零，会议与服务台多个区域为空，无法证明有数据图表、排行、详情和导出字段。
- **风险：权限视角单一。** 当前只证明采集账号可进入报表，无法定义子管理员的组织范围、成员详情、产品数据和导出权限。
- **风险：入口与结果分离。** 多个页面提供查看详情和导出，但本次均未执行，无法定义跳转传参、文件范围、任务状态和失败恢复。
- **风险：增值介绍与可用报表混淆。** 知识库和应用使用数据介绍包含较完整的能力说明，但当前证据不证明实际看板、下钻、导出或 API 已开通。
- **依赖：** 本文依赖 `prd-02` 的成员与组织对象、`prd-04` 的应用对象，以及各协作产品持续产生的使用数据；对象存在不等同于本文报表已具备对应统计口径。
