## 背景与问题

飞书企业管理后台通过“组织架构”和“对外协作”承载企业成员、部门、专业角色、用户分组、成员字段及关联组织等管理能力。当前产品缺少一份可追溯的现状规格，用于说明这些能力在当前租户登录视角下实际呈现的对象、入口、状态和限制。

本文基于 2026-08-14 对当前租户登录视角的页面采集，反推以下 7 个一级页面的现状：成员与部门、角色管理、单位管理、用户组管理、字段配置、人事企业版配置和关联组织。结论只来自 `src-001` 的页面 002-008 结构化提取与同名桌面截图，不扩写未进入的新建/编辑弹窗、详情、二级页签、批量操作、表单校验、提交结果、错误状态或受限能力内部页面。

当前成员列表的数据量较小，用户组和关联组织为无业务记录状态；单位管理与人事企业版配置展示版本受限的介绍/咨询页面。采集证据中的成员姓名、手机号等个人信息不在本文中复述，也不作为产品规则或验收样例。

## 目标与成功标准

### 产品目标

1. 为管理员提供成员、部门和离职成员的统一组织管理入口，并呈现当前组织层级、成员状态和可见操作。
2. 支持以专业角色和用户组组织成员，使审批人选择及其他后台管理场景能够引用相应组织对象。
3. 集中展示成员预置字段，并提供字段详情、搜索和相关配置入口。
4. 为单位级组织管理、人事企业版与关联组织提供清晰的可用状态、能力说明或管理入口。
5. 明确当前空数据、版本限制和未展开交互的证据边界，避免把入口或介绍页误写为已验证流程。

### 成功标准

1. 7 个页面均可从企业管理后台的“组织架构”或“对外协作”导航定位，并呈现本文列出的核心结构、状态和操作入口。
2. 成员列表有数据、用户组为空、关联组织为空，以及单位/人事能力受版本限制等当前状态均有可区分的用户反馈。
3. 角色管理能够展示当前系统角色与角色用途说明，字段配置能够展示预置字段分类、类型和详情入口。
4. 所有规格、验收记录和测试样例均不出现采集样本中的姓名、手机号、邮箱、用户 ID 或完整企业编号原值。
5. 未采集的新建、编辑、详情、批量、关联、提交、校验和受限页面内部行为不被当作已确认能力验收。

## 用户、角色与场景

| 用户/角色 | 触发场景 | 核心任务 | 当前证据边界 |
| --- | --- | --- | --- |
| 企业超级管理员 | 企业初始化或组织治理 | 查看组织树和成员；进入部门/成员、角色、用户组、字段及关联组织管理入口 | 当前采集账号可访问页面，但未证明各操作仅限超级管理员 |
| 具有组织架构权限的子管理员 | 日常维护成员与组织对象 | 搜索和筛选成员；查看成员状态；从可见入口发起部门、成员、角色或用户组管理 | 角色分配、部门可见范围及字段级权限未观察 |
| 人事管理员 | 处理人员信息和人事配置 | 切换人事管理模式，查看成员字段或进入人事企业版配置 | 人事管理模式未切换；人事企业版当前为受限介绍页 |
| 审批管理相关管理员 | 配置审批流程的角色审批人 | 查看专业角色，并通过角色保持审批职责的连续性 | 本次只观察到角色说明和系统角色列表，未进入成员分配或审批配置 |
| 对外协作管理员 | 建立或维护跨组织协作关系 | 搜索关联组织，查看共享范围，并进入全局设置、申请列表或邀请码分享 | 当前无关联组织；申请、分享和设置操作均未触发 |

主要场景包括：

1. 管理员进入成员与部门页，在组织树中定位当前组织，按账号状态或直属成员范围筛选成员，并从成员行进入详情。
2. 管理员按需要从可见入口新建部门、邀请或添加成员，或发起离职、部门变更和导入/导出等批量任务；本文仅确认入口存在。
3. 管理员查看专业角色及其审批用途说明，并搜索现有系统角色或进入新增、导入/导出入口。
4. 管理员创建静态用户组的前置查看场景：搜索用户组/分组，查看未分组节点和当前空态，并从新建、分组管理或导入/导出入口继续。
5. 管理员查看预置成员字段的分类和类型，按字段名或字段 ID 搜索，并从详情、帮助或 API 调用设置入口继续。
6. 管理员确认单位管理、人事企业版的当前版本可用性，或在关联组织页查看跨组织协作入口与当前空态。

## 范围

### 本次包含

- 成员与部门：基础管理模式、人事管理模式入口；成员、部门、已离职成员页签；组织树；成员搜索、账号状态与直属成员筛选；成员列表字段；部门/成员及批量操作入口；当前引导提示。
- 角色管理：角色搜索、当前系统角色列表、角色用途说明、新增角色、批量导入/导出和帮助入口。
- 单位管理：单位概念和用途说明、帮助与升级咨询入口、功能亮点、功能问答和套餐对比内容区。
- 用户组管理：静态用户组默认路由、用户组/动态用户组页签、搜索与分组树、空态、新建、分组管理和批量导入/导出入口。
- 字段配置：字段配置/展示/搜索/更多设置页签，预置/自定义字段页签，字段搜索、预置字段分类、字段类型、详情、帮助和 API 调用设置入口。

- 关联组织：搜索、关联方式筛选、关联组织列表字段、空态、帮助、全局设置、申请列表和邀请码分享入口。
- 当前可见的有数据、空数据、增值版本、套餐升级与页面引导状态。

### 不在本次范围

- 成员详情、成员新增/邀请、部门新建、离职、部门变更和导入/导出的字段、校验、确认、执行结果与错误处理。

- 角色新增、成员分配、更多菜单、编辑、删除和批量导入/导出的内部流程及审批应用中的实际配置结果。

## 用户故事

1. 作为组织架构管理员，我希望在组织树中搜索和筛选成员并查看其账号状态、所属部门，从而定位需要处理的组织对象。
2. 作为组织架构管理员，我希望看到部门、成员和批量管理入口，从而继续发起相应的日常维护任务。
3. 作为审批管理相关管理员，我希望查看专业角色及其用途说明，从而理解如何以角色承接审批职责。
4. 作为管理员，我希望按用户组或分组搜索，并看到当前空态和创建入口，从而开始建立跨部门的成员集合。
5. 作为人事或组织管理员，我希望查看成员预置字段的分类与类型，从而了解当前人员信息结构并进入字段详情或相关设置。
6. 作为企业管理员，我希望明确单位管理和人事企业版当前是否可用，从而选择查看帮助或联系升级。
7. 作为对外协作管理员，我希望搜索关联组织并查看双方共享范围，从而管理跨组织协作关系。

## 能力与信息架构

```text
企业管理后台
├── 组织架构
│   ├── 成员与部门
│   │   ├── 基础管理模式（当前）
│   │   ├── 人事管理模式（仅确认切换入口）
│   │   ├── 成员（当前）
│   │   ├── 部门（仅确认页签）
│   │   └── 已离职成员（仅确认页签）
│   ├── 角色管理
│   ├── 单位管理（当前版本受限）
│   ├── 用户组管理
│   │   ├── 用户组（当前静态用户组页）
│   │   └── 动态用户组（增值版本，仅确认页签）
│   ├── 字段配置
│   │   ├── 字段配置（当前）
│   │   │   ├── 预置字段（当前）
│   │   │   └── 自定义字段（仅确认页签）
│   │   ├── 字段展示（仅确认页签）
│   │   ├── 搜索设置（仅确认页签）
│   │   └── 更多设置（仅确认页签）
│   └── 人事企业版配置（当前版本受限）
└── 对外协作
    └── 关联组织
```

成员与部门提供当前企业的基础组织对象；角色和用户组以不同方式集合成员，其中页面明确角色当前用于审批应用流程设计，用户组可由任意部门或成员组成并供其他后台功能使用。字段配置描述成员信息结构。单位管理和人事企业版当前停留在版本介绍/咨询层，关联组织则提供跨企业共享范围的管理入口。未进入的页签、详情和操作不在本文中定义。

## 数据模型

本节描述页面上对管理员有意义的业务对象，不代表数据库或 API 设计。

| 业务对象 | 已观察字段/属性 | 对象关系与当前状态 |
| --- | --- | --- |
| 部门/组织节点 | 组织名称、总人数、层级入口 | 部门构成组织树；当前可见根组织和新建部门入口，部门详情字段及层级规则未观察 |
| 成员 | 姓名、账号状态、手机号码、部门、操作 | 成员归属可见部门；当前列表有数据且可见“正常”状态，具体姓名和手机号脱敏 |
| 专业角色 | 角色名称、系统角色标识 | 一个角色可由一位或多位成员组成；当前可见法务、IT、行政、财务、人事 5 个系统角色 |
| 单位 | 单位概念、关联部门关系、能力说明 | 页面说明单位高于部门层级，可将子公司或事业部作为单位并关联部门；当前套餐下实际单位对象未观察 |
| 静态用户组 | 用户组名称、所属分组 | 页面说明可将任意部门或成员加入一个或多个用户组；当前“未分组”计数为 0，暂无用户组 |
| 动态用户组 | 增值版本标识 | 仅确认页签存在，规则、成员范围和生命周期未观察 |
| 成员字段 | 字段名、字段 ID（搜索条件）、类型、操作 | 当前预置字段按基础信息、工作信息、个人信息、银行卡信息、证件信息、合同信息分类；可见类型包括文本、单选选项、人员、日期 |
| 人事企业版能力 | 产品说明、功能亮点、客户案例 | 当前为受限介绍页；实际组织人员、人事流程和 HRIS 配置对象未观察 |
| 关联组织 | 企业名称/完整企业编号（搜索条件）、我方共享范围、对方共享范围、关联方式、操作 | 用于跨组织协作；当前列表暂无关联组织，字段来自搜索条件和表头 |

## 权限与作用范围

1. 本次采集账号可以访问本文覆盖的 7 个页面及其当前可见入口，但该事实不能证明所有企业管理员具有相同的查看或操作权限。
2. `prd-01` 只证明超级管理员当前显示“全部权限”，并证明人事管理员存在部分人事相关权限范围；本文不据此推断页面 002-008 的逐项鉴权规则。

1. **隐私与脱敏**：规格、评审材料和测试记录仅描述个人及企业标识字段结构；姓名、手机号、邮箱、用户 ID 和完整企业编号使用占位符，不复述采集原值。

5. **版本状态隔离**：单位、人事和动态用户组的介绍或增值标识只表示当前登录视角的可见状态，不代表套餐资格、购买结果或功能实现细节。
