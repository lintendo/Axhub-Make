## 背景与问题

飞书企业管理后台在“费用中心”集中提供产品订阅、权益用量、订单、发票和支付通知邮箱的管理入口。当前产品已具备这些页面的一级信息架构，但缺少一份可追溯的现状规格，用于区分当前可见的产品事实、动态企业数据，以及尚未被采集验证的购买、订单、开票和账户编辑流程。

本文基于 2026-08-14 对当前租户登录视角的页面采集，反推以下 5 个一级页面的现状：我的产品、权益数据、订单列表、发票管理和账户管理。结论只来自 `src-001` 的页面 016 至 020 结构化提取与同名桌面截图，不扩写未展开的引导后状态、页签、详情、编辑弹窗、提交结果、错误状态或后台实现。

当前样本中，“我的产品”处于首次引导与无产品记录状态，“订单列表”和“账户管理”处于空态；“权益数据”展示多类权益用量；“发票管理”展示申请表，但没有可选择的开票账单。采集画面中的金额、通知邮箱、发票抬头、纳税人识别号/统一社会信用代码、银行信息及其他企业标识在本文中均以字段名或占位符表达，不作为固定产品规则。

## 目标与成功标准

### 产品目标

1. 建立企业已购产品、席位概况与订阅状态的统一查看入口。
2. 汇总 AI、存储、会议、自动化、数据库行数、管理员角色和 API 等权益的当前用量表达及可见关联入口。
3. 提供产品订单与 ISV 订单的分类入口，并在当前无订单时呈现清晰空态及开票、导出入口。
4. 提供发票申请、发票列表与发票信息管理入口，并在无可开票账单时保留当前可见的申请信息结构。
5. 提供支付通知邮箱的查看与编辑入口，并明确当前无通知邮箱数据的状态。

### 成功标准

1. 5 个页面均可从费用中心定位，并呈现本文列出的核心分区、字段、状态和操作入口。
2. 我的产品、订单列表、发票可开票账单和支付通知邮箱的当前空态均有明确可见反馈；我的产品的首次引导有可关闭或确认的入口。
3. 权益数据页能够区分不同权益对象，展示对应的用量/额度表达和当前可见的详情、管理、充值或升级入口。
4. 发票页在没有可选择账单时仍展示开票方、企业认证提示、账单字段、发票类型、抬头类型、发票信息和其他信息区域，但不以提交成功作为验收条件。
5. PRD、验收记录和测试样例不复述采集样本中的具体金额、邮箱、发票抬头、纳税人识别号/统一社会信用代码、银行信息或其他企业标识。
6. 未采集的购买、席位分配、订单详情/导出、开票提交、账户编辑、金额计算和税务处理不被当作已确认能力验收。

主要场景包括：

1. 管理员进入“我的产品”，查看当前企业版本、产品列表字段和首次引导，并在需要时使用专属客服或席位帮助入口。
2. 管理员进入“权益数据”，按权益卡片查看已用量/总量或当前周期用量，并进入当前可见的用量、管理、额度来源、充值或升级入口。
3. 管理员进入“订单列表”，在产品订单与 ISV 订单入口间定位订单类型；当前产品订单为空时，仍可见前往开票和导出订单入口。
4. 管理员进入“发票管理”，查看当前企业认证提示、可开票账单空态和发票申请表结构；不实际提交申请。
5. 管理员进入“账户管理”，查看支付通知邮箱空态并定位编辑入口；不实际编辑或保存。

## 用户故事

1. 作为具备费用中心访问权限的企业管理员，我希望查看已购产品的席位与订阅字段，从而了解企业当前产品状态并定位后续处理入口。
2. 作为企业管理员，我希望在同一页面查看多类权益的已用量与总量表达，从而识别当前资源使用情况并进入相关详情或管理入口。
3. 作为处理订单事项的管理员，我希望区分产品订单与 ISV 订单，并在无记录时仍能找到开票和导出入口，从而继续处理相关任务。
4. 作为处理发票事项的管理员，我希望查看企业认证提示、可开票账单和申请表结构，从而判断当前是否有可选择的账单以及需要准备哪些信息。
5. 作为维护支付通知设置的管理员，我希望查看通知邮箱的当前状态并找到编辑入口，从而定位支付通知配置。

## 能力与信息架构

```text
企业管理后台
└── 费用中心
    ├── 我的产品
    │   ├── 产品筛选与产品列表
    │   ├── 专属客服与席位帮助
    │   └── 首次引导/标准版空态
    ├── 权益数据
    │   ├── 企业级 AI 升级提示
    │   └── 权益用量卡片与关联入口
    ├── 订单列表
    │   ├── 产品订单（当前采集页签）
    │   ├── ISV 订单（仅确认页签入口）
    │   └── 前往开票、导出订单与更多入口
    ├── 发票管理
    │   ├── 发票申请（当前采集页签）
    │   ├── 发票列表（仅确认页签入口）
    │   └── 发票信息管理（仅确认页签/入口）
    └── 账户管理
        └── 支付设置
            └── 接收通知的邮箱
```

费用中心以企业为作用范围，将产品与权益查看、订单入口、发票申请入口和支付通知配置入口放在同一导航分组。页面之间存在“订单列表 -> 前往开票”和“权益数据 -> 对应资源/用量页面”等可见入口，但跳转后的完整路径及业务结果未采集，因此本文不定义跨页面状态同步。

## 权限与作用范围

1. 本次采集账号可以访问本 PRD 覆盖的 5 个页面及其当前可见入口，但该事实不能证明所有企业管理员都具有相同权限。
2. 页面均以当前企业为作用范围展示产品、权益、订单、发票和支付通知设置；多企业切换、跨企业查看和数据隔离行为未采集。
3. 联系专属客服、立即升级、前往充值、席位分配、订单导出、前往开票、发票提交和账户编辑的执行权限均未验证。
4. 当前未采集无权限角色视角，因此不定义页面隐藏、按钮禁用、拦截提示或权限申请流程。
5. 发票页当前显示企业未认证提示，但不能据此推断认证状态是所有发票字段或操作的唯一权限条件。
