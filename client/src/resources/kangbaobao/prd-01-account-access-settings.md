## 背景与问题

康宝宝原型以手机号和短信验证码作为主要访问入口，并在设置页集中展示手机号、第三方账号状态、系统通知、版本、缓存和退出账号入口。当前资料来自 Axure 高保真原型，只能证明页面、可见文案和已定义交互，不能证明真实短信、认证、第三方授权、会话或数据持久化已经存在。

本 PRD 固化当前原型可验证的账号访问与设置体验，并将生产规则缺口保留为开放问题。

## 目标与成功标准

- 用户可从启动页进入手机号验证码登录页，并完成获取验证码、提交登录的页面流程。
- 登录成功后，页面能根据“首次登录”或“非首次登录”分支分别进入宝宝信息建立流程或首页。
- 用户可从设置页发起手机号更换，完成新手机号录入和验证码提交的页面流程。
- 设置页完整呈现原型已有的绑定状态、系统通知、版本检查、缓存清理和退出账号入口。
- 所有成功、错误、倒计时和确认状态均可按原型交互定义验收；未有证据的后台结果不作为交付事实。

## 用户、角色与场景

| 用户/角色 | 场景 | 核心任务 |
| --- | --- | --- |
| 家长/照护者（由产品内容推断） | 首次或再次访问产品 | 使用手机号与验证码登录 |
| 已进入产品的用户 | 更换后续登录所用手机 | 在设置中绑定新手机号并提交验证码 |
| 已进入产品的用户 | 管理客户端账号相关选项 | 查看绑定状态、开关系统通知、检查版本、清理缓存或退出账号 |

## 范围

### 本次包含

- 启动页分步显现并进入登录页。
- 登录页的手机号、验证码、获取验证码、倒计时、再次获取、登录按钮、用户协议文案和其他登录方式展示。
- 登录提交的漏填/错填提示入口，以及验证通过后的首次/非首次分支。
- 设置页的手机号和第三方账号绑定状态展示、系统通知、检查新版本、清除缓存和退出账号入口。
- 更换手机号的手机号录入、格式错误提示、验证码页、重新获取倒计时、验证码错误提示和返回设置页。
- 退出账号确认层及确认/取消路径。

### 不在本次范围

- 短信供应商、真实验证码生成与发送、风控、频控、认证协议和接口设计。
- 第三方账号真实登录/绑定/解绑授权流程；登录页只保留原型已有的展示。
- 会话有效期、自动登录、多设备登录、账号注销、数据删除与账号找回。
- 操作系统通知权限申请、版本发布系统、应用商店跳转和缓存实现机制。
- 用户协议正文及其承载页面。

## 用户故事

1. 作为首次使用的家长/照护者，我希望用手机号和验证码登录，从而继续建立宝宝资料。
2. 作为再次使用的家长/照护者，我希望验证通过后直接进入首页，从而继续使用已有产品入口。
3. 作为已进入产品的用户，我希望更换绑定手机号，从而使用新号码登录康宝宝。
4. 作为已进入产品的用户，我希望在设置页查看和操作账号相关选项，从而管理当前客户端状态或退出账号。

## 能力与信息架构

```text
启动页
└── 登录
    ├── 首次登录验证通过 → 宝宝性别（PRD-02）
    └── 非首次登录验证通过 → 首页

我的 → 设置
├── 手机号 → 绑定新手机号 → 输入验证码 → 设置
├── 微博 / 微信 / QQ 绑定状态
├── 系统通知
├── 检查新版本
├── 清除缓存
└── 退出账号 → 登录
```

| 账号绑定展示 | 手机号、微博、微信、QQ | 示例状态为手机号 `188****8766`、微博 `Alex`、微信/QQ“未绑定” |
| 客户端设置 | 系统通知、版本检查、缓存大小 | 默认页展示通知开关、检查新版本、清除缓存及示例值 `207M` |
| 换绑手机表单 | 新手机号、验证码、掩码号码 | 新手机号页有一个输入框；验证码页展示已发送提示和掩码号码 |

## 业务规则

| 编号 | 条件 | 动作 | 原型已定义结果 |
| --- | --- | --- | --- |
| AR-01 | 启动页加载 | 依次显示启动插画和页面元素并等待 | 当前窗口打开登录页 |
| AR-02 | 登录页点击“获取验证码”，且进入名为“手机号码正确”的交互分支 | 将计时器设为 60，并禁用获取按钮 | 按秒展示倒计时；计时完成后启用按钮并显示“再次获取” |
| AR-03 | 点击登录，进入“漏填错填提示”分支 | 展示提示 | 约 1500 ms 后隐藏提示；具体错误文案和判断条件未采集 |
| AR-04 | 点击登录，进入“验证通过（初次登录）”分支 | 展示提示并等待 | 当前窗口打开“宝宝性别” |
| AR-05 | 点击登录，进入“验证通过（非初次登录）”分支 | 展示提示并等待 | 当前窗口打开首页 |
| AR-06 | 在设置页点击手机号行 | 发起更换手机号 | 当前窗口打开“绑定新手机号” |
| AR-07 | 新手机号提交进入“漏填错填提示”分支 | 展示“手机号码格式错误” | 约 1500 ms 后隐藏提示 |
| AR-08 | 新手机号提交进入“验证通过”分支 | 继续验证 | 当前窗口打开“输入验证码” |
| AR-09 | 验证码页加载或重新获取 | 将计时器设为 60 | 倒计时显示“`n s 后可重新获取`”，期间按钮禁用，结束后显示“再次获取”并启用 |
| AR-10 | 提交验证码进入错误分支 | 展示“验证码错误” | 约 1500 ms 后隐藏提示 |
| AR-11 | 提交验证码进入验证通过分支 | 展示成功反馈并等待 | 当前窗口返回设置页 |
| AR-12 | 点击退出账号 | 展示确认层 | 取消关闭确认层；确认显示成功反馈后打开登录页 |

补充边界：原型中的“手机号码正确”“验证通过”“首次登录”等是交互分支名称，并没有给出可实施的判定规则。因此本 PRD 不把手机号位数、验证码长度、有效期、重试上限或首次登录识别方式写成事实。

## 状态、异常与边界

| 场景 | 状态/边界 | 用户可见结果 |
| --- | --- | --- |
| 登录页默认态 | 手机号和验证码均待输入 | 显示“请输入手机号”“请输入验证码”“获取验证码” |
| 获取验证码 | 60 秒倒计时 | 获取入口不可重复点击，倒计时结束后变为“再次获取” |
| 登录提交异常 | 漏填或错填分支 | 显示短暂提示；具体字段级规则待确认 |
| 登录提交成功 | 首次/非首次两个分支 | 分别进入宝宝性别页或首页 |
| 新手机号异常 | 手机号格式错误分支 | 显示短暂错误提示并留在当前页 |
| 换绑验证码异常 | 验证码错误分支 | 显示短暂错误提示并留在当前页 |
| 换绑验证码成功 | 验证通过分支 | 显示反馈并返回设置页；是否已真实换绑待确认 |
| 设置默认态 | 绑定状态与客户端状态 | 展示掩码手机号、社交绑定状态、系统通知、版本和缓存信息 |
| 退出账号 | 待确认/取消/确认 | 确认后进入登录页；本地数据、会话和推送状态如何变化待确认 |

没有证据的短信发送失败、网络失败、验证码过期、频率受限、账号冲突、第三方授权失败、版本检查结果、缓存清理失败等状态不在当前事实范围内。

| 页面 | 字段/内容 | 交互要求 |
| --- | --- | --- |
| 启动页 | 启动插画和背景元素 | 页面加载后按原型顺序显现，最终在当前窗口进入登录页 |
| 登录 | 手机号输入、验证码输入、获取验证码、登录按钮、“登录即代表同意 用户协议”、其他登录方式图标 | 输入框和按钮布局与原型一致；用户协议保持可识别的强调样式；第三方真实能力不作为本次验收项 |
| 设置 | 手机号、微博、微信、QQ、系统通知、检查新版本、清除缓存、退出账号 | 手机号行进入更换流程；通知提供开关视觉状态；绑定行、版本、缓存交互只验收原型已定义的状态反馈，不推断真实外部结果 |
| 绑定新手机号 | 说明文案、手机号输入框、“绑定”按钮 | 返回保留为上一级导航；错误分支展示格式错误，验证通过进入验证码页 |
| 输入验证码 | “短信验证码已经发送到”、掩码号码、验证码输入、提交、倒计时/再次获取 | 页面加载即开始 60 秒倒计时；提交错误留在本页，提交成功返回设置页 |
| 退出确认层 | 确认与取消路径 | 取消只关闭确认层；确认完成反馈后进入登录页 |

原型登录页底部三个其他登录方式的可见提取文案均为“微信”，截图图标表现并不一致，且未采集到对应登录跳转；交付时不得据此自行命名或接入第三方服务。

## 验收标准与来源追溯

### 产品验收

1. 从启动页完成原型定义的分步显现后，可在当前窗口进入登录页。
2. 登录页完整展示手机号、验证码、获取验证码、登录、用户协议和其他登录方式区域。
3. 获取验证码进入正确分支后，按钮从 60 秒开始倒计时，倒计时期间不可再次触发，结束后显示“再次获取”并恢复可用。
4. 登录提交可演示漏填/错填提示、首次登录成功进入“宝宝性别”、非首次登录成功进入首页三个分支。
5. 设置页完整展示四类账号绑定信息及系统通知、版本、缓存、退出账号入口；示例数据与原型一致。
6. 点击手机号可进入“绑定新手机号”；合法/错误分支分别进入验证码页或展示格式错误提示。
7. 验证码页加载后开始 60 秒倒计时；错误分支展示“验证码错误”，验证通过分支返回设置页。
8. 退出账号先展示确认层；取消留在设置页，确认完成反馈后进入登录页。

### 设计验收

- 页面标题、字段顺序、主要文案、掩码展示、按钮层级、开关与确认层关系与对应默认态截图一致。
- 验证码倒计时、短暂反馈、返回和页面跳转与对应 JSON 中的 Axure 交互定义一致。
- 不把原型外侧的“咨询作者”“作品主页”等模板控件纳入产品界面。

### 实现验收

- 所有页面跳转使用当前产品内的对应目标页面；返回入口回到上一级页面。
- 在未确定真实服务前，可以验证页面分支和状态切换，但不得把模拟成功描述成真实短信、认证、换绑或第三方授权成功。
- 登录与换绑表单的生产级校验、网络错误和持久化只有在开放问题确认后才能作为实现验收项。

### 回归风险

- PRD-02 依赖首次登录进入“宝宝性别”的分支；修改登录成功去向时需回归宝宝建档链路。
- PRD-07 提供从“我的”进入设置的入口；设置入口或退出结果变化时需回归个人中心导航。
- 登录页第三方图标与提取文案不一致，替换文案或接入服务前需先完成产品确认。

- 风险：当前只有原型分支名称，若直接实施可能把演示分支误当作生产校验或认证逻辑。
