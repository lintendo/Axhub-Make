## 背景与问题

宝宝档案是成长记录、日记和疫苗等后续能力的主体。原型提供了首次登录后建档、从“我的宝宝”添加宝宝、在首页切换或编辑宝宝、查看多个宝宝卡片，以及左滑删除的页面流程。

当前来源能证明界面中存在多张宝宝卡片、宝宝字段和相应交互，但不能证明账号与宝宝的真实数据关系、当前宝宝切换的持久化、删除语义、头像上传、生日边界或字段校验已经确定。本 PRD 仅固化可观察的档案体验。

## 目标与成功标准

- 首次登录用户和已有用户都可进入宝宝新增流程，并依次完成性别选择、基础信息填写和返回“我的宝宝”的页面链路。
- 用户可在“我的宝宝”查看多张宝宝档案卡片，通过卡片进入首页，并通过首页入口访问档案编辑页。
- 用户可从档案编辑页访问头像、昵称、性别、出生日期、身高和体重相关入口。
- 用户可演示左滑删除、取消和确认后的成功反馈，不把未证实的永久删除或数据联动写成既定规则。
- 页面字段、示例值、反馈和跳转均能追溯到具体 Axure 页面证据。

## 用户、角色与场景

| 用户/角色 | 场景 | 核心任务 |
| --- | --- | --- |
| 首次登录的家长/照护者（由产品内容推断） | 尚未建立宝宝资料 | 选择宝宝性别，填写昵称、头像和出生日期 |
| 已进入产品的家长/照护者 | 家庭中存在一个或多个宝宝 | 查看宝宝卡片、添加宝宝或从卡片进入首页 |
| 已进入产品的家长/照护者 | 宝宝资料发生变化或录入有误 | 修改头像、昵称、性别和出生日期，进入身高/体重编辑入口 |
| 已进入产品的家长/照护者 | 不再需要某张档案 | 左滑卡片并使用删除确认层 |

## 范围

### 本次包含

- “我的宝宝”列表、添加宝宝入口、宝宝卡片、左滑删除态、确认层和删除成功反馈。
- 宝宝性别页的男孩/女孩选择及进入宝宝信息页。
- 宝宝信息页的头像入口、昵称输入、出生日期入口和“确定”动作。
- 首页顶部宝宝信息区域进入“修改宝宝信息”或“我的宝宝”的路径。
- 修改宝宝信息页中的头像、昵称、性别、出生日期、身高、体重展示与入口。
- 修改宝宝昵称页的输入、清空控件、提示文案、保存成功反馈和返回编辑页。

### 不在本次范围

- 账号与宝宝的后台关联、档案持久化、同步、共享、监护人权限和宝宝数量上限。
- 头像来源、图片格式、裁剪、压缩、上传、权限和失败处理。
- 出生日期可选范围、日期格式本地化、年龄/月龄计算和时区规则。
- 昵称生产级字符统计、敏感词、重名和错误提示规则。
- 删除的软删/硬删、恢复、关联成长记录处理及不可逆警告。
- 身高、体重的录入、校验和记录计算；对应能力归 PRD-03。

## 用户故事

1. 作为首次登录的家长/照护者，我希望建立宝宝基础档案，从而进入与宝宝相关的产品体验。
2. 作为照护多个宝宝的用户，我希望查看并选择宝宝卡片，从而进入相应宝宝的首页。
3. 作为已建立档案的用户，我希望修改宝宝头像、昵称、性别和出生日期，从而保持资料与当前情况一致。
4. 作为不再需要某张档案的用户，我希望先确认再执行删除，从而避免直接误触。

## 能力与信息架构

```text
首次登录验证通过（PRD-01）
└── 宝宝性别 → 宝宝信息 → 我的宝宝

我的 → 宝宝管理 → 我的宝宝
├── 添加宝宝 → 宝宝性别 → 宝宝信息 → 我的宝宝
├── 宝宝卡片 → 首页
└── 宝宝卡片左滑 → 删除确认 → 我的宝宝

首页顶部宝宝信息
├── 修改宝宝信息
│   ├── 宝宝头像（弹层）
│   ├── 昵称 → 修改宝宝昵称 → 修改宝宝信息
│   ├── 性别（弹层）
│   ├── 出生日期（日期层）
│   └── 身高 / 体重 → 增加/编辑记录（PRD-03）
└── 我的宝宝
```

## 数据模型

这里只描述用户可感知的对象和字段，不推断数据库结构或持久化方式。

| 对象 | 字段/状态 | 已观察说明 |
| --- | --- | --- |
| 宝宝档案 | 头像、昵称、性别、出生日期、身高、体重 | 修改页展示全部六类信息；身高和体重带 `cm`、`kg` 单位 |
| 宝宝卡片 | 性别图标、昵称、年龄/月龄、进入入口 | “我的宝宝”默认态展示两张示例卡片，均为“梓宁宝宝”“6个月” |
| 新增宝宝草稿 | 性别、头像入口、昵称、出生日期 | 性别先独立选择；基础信息页提供头像、昵称和日期入口 |
| 宝宝卡片交互态 | 初始、删除 | 卡片动态面板定义“初始”“删除”两种状态 |
| 昵称编辑 | 当前昵称、清空控件、保存 | 示例输入为 `Alex`；页面显示长度说明 |

UI 可以同时展示多张宝宝卡片，但一个账号可关联多少宝宝、哪一张是“当前宝宝”、选择结果是否持久化，均没有来源证据。

## 业务规则

| 编号 | 条件 | 动作 | 原型已定义结果 |
| --- | --- | --- | --- |
| BP-01 | 首次登录验证通过，或用户点击“添加宝宝” | 进入建档 | 当前窗口打开“宝宝性别” |
| BP-02 | 在宝宝性别页点击男孩或女孩 | 选择一个可见性别选项 | 当前窗口打开“宝宝信息”；选择值如何传递未提供证据 |
| BP-03 | 在宝宝信息页点击头像区域 | 发起头像选择 | 显示“上传照片”层；层内容和上传结果未展开采集 |
| BP-04 | 在宝宝信息页点击出生日期区域 | 发起日期选择 | 显示日期选择层；确认或取消均可关闭该层 |
| BP-05 | 在宝宝信息页点击“确定” | 提交页面信息 | 显示短暂反馈后打开“我的宝宝”；字段判定与持久化未提供证据 |
| BP-06 | 在“我的宝宝”点击卡片 | 进入该卡片对应的页面路径 | 当前窗口打开首页；是否设置为当前宝宝待确认 |
| BP-07 | 在宝宝卡片上左滑/右滑 | 切换卡片交互态 | 左滑进入“删除”态，右滑返回“初始”态 |
| BP-08 | 在删除态点击删除入口 | 请求删除 | 显示确认层 |
| BP-09 | 在确认层取消 | 取消本次操作 | 关闭确认层并保留当前页面 |
| BP-10 | 在确认层确认 | 执行原型删除路径 | 关闭确认层、显示约 1500 ms 的“删除成功”反馈，再打开“我的宝宝” |
| BP-11 | 在首页点击顶部宝宝资料入口 | 查看或切换档案 | 原型分别定义进入“修改宝宝信息”和“我的宝宝”的点击路径 |
| BP-12 | 在修改宝宝信息页点击头像、性别或出生日期 | 编辑对应字段 | 分别显示头像层、性别层或日期层；选择结果未展开采集 |
| BP-13 | 在修改宝宝信息页点击昵称 | 编辑昵称 | 当前窗口打开“修改宝宝昵称” |
| BP-14 | 昵称文本发生变化 | 提供快捷清空 | 显示清空控件；点击后清空/更新输入显示 |
| BP-15 | 点击昵称“保存”，进入“修改成功”分支 | 提交昵称 | 显示约 1000 ms 的成功反馈，随后返回“修改宝宝信息” |
| BP-16 | 在修改宝宝信息页点击身高或体重 | 编辑成长数据 | 当前窗口打开“增加/编辑记录”；字段规则归 PRD-03 |

新增页文案要求“输入宝宝昵称，2-10个字符”，修改昵称页则显示“英文字母或汉字，限4-16个字符，一个汉字为2个字符”。两处规则存在冲突，不能合并成统一校验事实。

## 权限与作用范围

- 原型只呈现一个通用用户角色，未提供查看、编辑、删除宝宝档案的角色差异或监护人权限。
- 本 PRD 仅要求进入产品的用户可看到上述入口；不定义账号间共享、协作照护或管理员能力。
- 后续成长记录、日记和疫苗应作用于哪一张宝宝档案，需在“当前宝宝”规则确认后由 PRD-03、PRD-04 复用。

## 状态、异常与边界

| 场景 | 状态/边界 | 用户可见结果 |
| --- | --- | --- |
| 我的宝宝默认态 | 有多张示例卡片 | 每张卡片显示性别图标、昵称、月龄和进入箭头 |
| 宝宝列表空态 | 未采集 | 不补造空态文案或默认跳转 |
| 卡片删除 | 初始、左滑删除、确认、成功、取消 | 只按原型演示状态切换；真实删除及关联数据结果待确认 |
| 新增建档 | 性别选择、基础信息输入、提交 | 页面按顺序跳转；必填项、禁用态和错误态未证实 |
| 头像/性别/日期编辑 | 弹层显示、关闭 | 选择项、结果回填、相机/相册权限和失败态未展开采集 |
| 昵称编辑 | 默认值、文本变化、清空、保存成功 | 显示页面级长度说明；错误态和边界判定未采集 |
| 身高/体重入口 | 当前页展示示例值 | 点击进入成长记录编辑页；不在本 PRD 定义其保存结果 |

## 字段、内容与交互要求

| 页面 | 字段/内容 | 交互要求 |
| --- | --- | --- |
| 我的宝宝 | 标题、“添加宝宝”、宝宝卡片列表 | 添加进入宝宝性别；卡片点击进入首页；卡片支持左右滑状态切换和删除确认 |
| 宝宝性别 | “完善宝宝信息”“请选择宝宝性别”、男孩、女孩 | 任一性别卡片点击后进入宝宝信息页；返回回到上一级 |
| 宝宝信息 | 头像入口、昵称输入、出生日期入口、“确定” | 头像与日期分别打开对应层；确定展示反馈并进入我的宝宝 |
| 修改宝宝信息 | 标题使用示例宝宝名；头像、昵称、性别、出生日期、身高、体重 | 各行提供进入箭头；头像/性别/日期打开层，昵称进入昵称编辑，身高/体重进入成长记录编辑 |
| 修改宝宝昵称 | 当前昵称输入、清空控件、长度说明、“保存” | 文本变化后显示清空控件；保存成功反馈后返回修改宝宝信息 |

默认态示例值包括：昵称“梓宁”、性别“女”、出生日期 `2019/06/19`、身高 `55cm`、体重 `15kg`。这些是原型演示内容，不代表新建档案默认值或生产数据。

## 验收标准与来源追溯

### 产品验收

1. 首次登录成功和“我的宝宝”的“添加宝宝”均可进入宝宝性别页。
2. 宝宝性别页同时展示男孩、女孩两个选项；点击任一选项均进入宝宝信息页。
3. 宝宝信息页展示头像、昵称、出生日期和确定操作；头像与日期入口可打开相应层，确定后展示反馈并进入“我的宝宝”。
4. “我的宝宝”可同时展示多张宝宝卡片；点击卡片进入首页。
5. 宝宝卡片左滑进入删除态、右滑回到初始态；删除入口先显示确认层，取消保留页面，确认显示“删除成功”后回到“我的宝宝”。
6. 从首页顶部宝宝信息区域可分别进入“修改宝宝信息”和“我的宝宝”。
7. 修改宝宝信息页完整展示头像、昵称、性别、出生日期、身高和体重；对应入口按原型打开弹层或目标页面。
8. 修改宝宝昵称页展示当前值、清空控件和长度说明；保存成功后返回修改宝宝信息页。
9. 验收过程不得把卡片点击、删除反馈、昵称保存反馈解释为已完成后台持久化。

### 设计验收

- 页面标题、字段顺序、示例值、卡片层级、进入箭头、左右滑删除和反馈层与对应默认态截图及交互定义一致。
- 新增页和昵称编辑页各自保留原型可见的长度文案，不擅自统一冲突规则。
- 不把原型外侧的“咨询作者”“作品主页”等模板控件纳入产品界面。

### 实现验收

- 建档、列表、编辑和删除路径均可在前端按原型演示，返回和目标页面正确。
- 未确认数据服务前，不要求多宝宝持久化、真实删除、头像上传或日期/年龄计算；这些能力不得以静态示例伪装为已实现的生产结果。
- 身高/体重行只验收进入“增加/编辑记录”的路径，其字段和保存验收归 PRD-03。

### 回归风险

- PRD-01 的首次登录成功分支直接依赖宝宝性别页；建档入口变化需回归登录流程。
- PRD-03、PRD-04 的记录和疫苗范围将依赖当前宝宝作用域；切换/删除规则确认后需同步回归下游模块。
- 新增与修改昵称长度文案冲突，任何统一规则都可能改变现有页面事实。

## 风险与依赖

- 风险：原型成功反馈不证明真实保存或删除，若未先明确数据边界，可能造成用户误解或关联记录丢失。
- 风险：多宝宝卡片可见但当前宝宝规则缺失，会影响首页、成长、日记和疫苗的数据归属。
- 风险：昵称规则在新增与修改页面冲突，会导致实现和验收口径不一致。
- 依赖：PRD-01 提供首次登录入口；PRD-03、PRD-04 需复用本模块最终确认的当前宝宝作用域。

## 开放问题

| 问题 | 影响 | 当前假设/处理 |
| --- | --- | --- |
| 一个账号最多可建立多少宝宝，是否支持多照护者共享？ | 列表、权限、数据模型 | 不作假设；仅验收多卡展示 |
| 点击宝宝卡片是否将其设置为当前宝宝，当前选择如何展示、持久化并影响首页/记录/疫苗？ | 全部宝宝相关模块 | 只验收卡片进入首页，不宣称已切换作用域 |
