# 固定文档模板设置设计

## 背景与目标

Make Client 当前把 PRD、规格文档和评审报告模板放在 `src/resources/templates/`，并沿用资源目录的动态扫描、创建、复制、重命名和删除能力。模板实际是产品预置的固定系统文件，这套资源管理方式增加了入口和维护复杂度。

本次调整为：模板文件移到项目根层独立的 `templates/` 目录，在“设置 > 项目设置”中提供固定模板列表，只允许预览和编辑。普通自定义文档继续放在 `src/resources/`，不进入模板设置。

## 方案选择

采用“固定 ID 注册表 + 固定读写接口”方案：代码声明模板清单和文件映射，服务端不扫描目录，页面不提供自定义模板管理。

不采用以下方案：

- 不区分系统模板和项目模板。
- 不保留资源目录中的动态模板入口。
- 不增加模板创建、导入、复制、重命名或删除。
- 不增加 `templates/manifest.json`；模板清单只有代码中的固定注册表一份。

## 固定模板与目录

模板文件统一使用英文稳定文件名：

| 固定 ID | 显示名称 | 文件 |
| --- | --- | --- |
| `prd` | PRD 模板 | `templates/prd.md` |
| `prototype-spec-md` | Markdown 规格文档模板 | `templates/prototype-spec.md` |
| `prototype-spec-html` | HTML 规格文档模板 | `templates/prototype-spec.html` |
| `prototype-review` | 原型评审报告模板 | `templates/prototype-review.md` |
| `ui-review` | UI 评审报告模板 | `templates/ui-review.md` |

新增共享固定注册表，记录 ID、显示名称、格式、用途和相对路径。服务端以 ID 查表取得路径，前端以 ID 处理选择和打开，不把中文文件名或物理路径作为业务标识。

`client/template-manifest.json` 在 `runtime.files` 中显式发布这五个文件，并从 `resources.files` 移除旧路径。`src/resources/` 只保留普通资源。

## 项目设置入口

在现有“项目设置”页增加“文档模板”区块，按注册表顺序显示固定列表。每项展示名称、格式和简短用途，并提供“预览”和“编辑”操作。

该区块不提供新增、删除、复制、导入、重命名或排序。模板也不再出现在通用资源模板目录中；新建文档需要选择模板时，仍从同一固定注册表取得可用项。

## 读写与预览

新增固定接口：

```http
GET /api/document-templates
GET /api/document-templates/:id
PUT /api/document-templates/:id
```

- 列表接口只返回注册表中的固定项及其格式、用途、可用状态和打开地址。
- 读取和保存接口只接受已登记 ID，文件路径完全由注册表生成。
- `PUT` 只更新模板正文，不接受路径、名称或格式变更。
- 未知 ID 返回 404；创建、删除、复制和重命名不提供接口。

Markdown 模板复用现有 Markdown 文档预览和编辑能力。HTML 模板复用现有同源 iframe 预览，并继续通过 `HtmlTemplateBootstrap` 提供快速编辑；本次不新增 HTML 源码编辑器。HTML 模板的固定接口地址需要加入现有 HTML 文档预览和编辑桥接的识别范围。

## 调用方调整

- PRD 编写、规格文档生成、原型评审和 UI 评审统一改用新模板路径或固定 ID。
- 规格文档格式选择继续分别映射 `prototype-spec-md` 和 `prototype-spec-html`。
- 技能、规则、提示词常量和测试中的旧 `src/resources/templates/` 路径同步更新。
- 通用资源页面不再加载或管理模板；普通自定义 Markdown、HTML 等文档仍按现有资源流程处理。

## 迁移与兼容边界

仓库内五个现有模板直接移动并改名，内容保持不变；统一 PRD 模板继续沿用已经确认的默认章节和“（可选）”章节标记。

不为 `src/resources/templates/`、中文旧文件名或 `/api/docs/templates` 增加别名、回退扫描和双写逻辑。同一仓库内的调用方在本次改动中一次性切换；已有业务文档不移动、不改写。

## 安全与失败处理

- 所有文件访问都从固定 ID 查表，并校验最终路径位于项目根层 `templates/` 内。
- 接口不接收任意相对路径或文件名，避免越权读写项目文件。
- 模板文件缺失时列表标记不可用，打开时返回明确错误，不自动生成空文件。项目设置提供“恢复默认模板”，用户确认后从当前官方客户端模板来源补回该文件；恢复只处理缺失项，不覆盖其他已经存在或被编辑的模板。
- 正常项目更新只补齐缺失的 `templates/` 文件，不覆盖用户已经编辑的模板内容。
- HTML 继续沿用现有同源预览、内容重写和快速编辑安全边界。

## 验证

- 注册表测试确认固定 ID、顺序、格式和路径唯一且完整。
- 服务端测试确认固定列表可读、正文可保存，未知 ID 和任意路径被拒绝，且不存在创建、删除、复制、重命名能力。
- 缺失场景测试确认列表保留缺失项、预览返回 404、恢复默认模板只补回目标文件，并且项目更新不覆盖现有模板。
- 项目设置测试确认显示五个固定模板及预览、编辑操作，不出现自定义模板管理入口。
- Markdown 预览/编辑和 HTML iframe 预览/快速编辑分别通过回归测试。
- 规格文档、PRD、原型评审和 UI 评审测试确认使用新 ID 或新路径。
- 发布清单测试确认五个新文件进入运行时，旧资源模板路径全部移除。
- 运行相关 Vitest、`pnpm admin:build`，并在完整 Make 页面验证项目设置中的两种格式模板均能打开和保存。

## 完成标准

- 五个固定模板位于独立 `templates/` 目录，并随客户端模板发布。
- 项目设置是固定模板的唯一配置入口。
- 固定模板仅支持预览和编辑，不存在自定义模板管理能力。
- Markdown 和 HTML 分别复用现有文档能力，HTML 不新增独立源码编辑器。
- `src/resources/` 与模板职责分离，旧动态模板入口和旧路径不再被使用。
