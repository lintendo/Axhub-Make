# 数据驾驶舱内置风格对齐与发布图片优化设计

## 目标

更新 `generate-data-cockpit-prototype` Skill，使数据驾驶舱在生成候选图前，使用项目内置的数据可视化风格资料完成板块、布局、设计风格和主题色对齐，不再依赖系统默认的 `DESIGN.md` 候选流程。

同时优化 8 张 4K 风格参考图的发布体积。图片继续保留 3840×2160 分辨率和足以判断构图、配色、信息密度及材质效果的视觉质量，但不再以大体积 PNG 随包发布。

## 范围

本次修改仅覆盖：

- `generate-data-cockpit-prototype` 的前期设计对齐和候选图提示词组织。
- `.agents` 与 `.claude` 两份 Skill 镜像。
- `data-visualization-style-reference` 中 8 张 4K 参考图及其 Markdown 引用。
- 对应 Skill 和资源契约测试。

不修改全局 `requirements-alignment-guide.md` 的默认 `DESIGN.md` 流程，也不改变其他原型 Skill 的设计对齐方式。普通尺寸预览图不在本次优化范围内。

## 设计输入与优先级

前期需求对齐继续确认目标角色、核心任务、展示环境、行业语义、数据重点、地图和 3D 倾向，并补充以下设计决策：

1. 业务板块、核心指标与信息优先级。
2. 顶部、左右、中部和底部的布局关系。
3. 中央载体采用 GIS、2.5D、3D、拓扑还是纯 BI 分析。
4. 整体设计风格、明暗倾向和信息密度。
5. 主色、辅助色、状态色与告警色。
6. 用户参考图中需要继承的构图、配色、材质或氛围。

设计输入按以下优先级处理：

1. 用户提供的参考图。
2. 用户明确提出的布局、风格和主题色要求。
3. 项目内置的 8 套数据可视化风格。

用户约束与内置风格冲突时，以用户最新明确要求为准。用户提供的是待直接还原的完整截图，且不需要重新生成候选图时，转交 `screenshot-to-prototype`，不进入本流程。

## `DESIGN.md` 例外规则

本 Skill 是 client 系统默认设计对齐流程的明确例外。

- 仍需读取 `rules/requirements-alignment-guide.md` 以完成产品需求对齐。
- 必须跳过其中的 `DESIGN.md` 候选、主题深链和设计基底确认步骤。
- 不要求用户选择现有主题，不新建 `DESIGN.md`，也不从 `DESIGN.md` 复用 tokens 来约束候选图。
- 改用“用户参考图 → 用户明确设计要求 → 内置风格推荐”的顺序，与用户确认数据驾驶舱的设计方向。
- 后续选中的候选图片仍是全部可见视觉事实的唯一还原标准；前期风格资料不能反向纠正选中图片。

该例外只写入 `generate-data-cockpit-prototype` 及其测试，不扩大为其他原型的全局规则。

## 内置风格推荐

权威风格资料继续存放在：

`src/resources/data-visualization-style-reference/visualization-style-prompts.md`

Skill 新增轻量引用文档 `references/style-alignment.md`，只保存选择流程、输入优先级、推荐维度和输出契约，不复制 8 套完整提示词或图片。完整内容仍由资源目录单点维护。

用户没有提供参考图、风格、布局或主题色时：

1. 根据行业匹配度、数据密度、GIS/3D 倾向、明暗倾向和文化气质评估 8 套风格。
2. 推荐 3 套有实质差异的候选方向，避免只改变颜色而保持同一构图。
3. 每套候选向用户展示：风格名称、参考图、推荐理由、主要板块与布局、中央载体、主题色和主要取舍。
4. 默认使用这 3 套方向各生成 1 张候选图；用户明确指定候选数量时，以用户数量为准。
5. 等待用户选图后再进入规格阶段。

用户已提供明确设计输入时，不强制重新推荐 3 套内置风格。内置资料可以用于补全用户没有说明的细节，但不能覆盖用户要求。

## 提示词构建

生成候选图时，把对应风格的完整提示词作为结构骨架，而不是只摘取风格名称或少量关键词：

- 替换行业、标题、中央载体、核心业务对象和关键指标。
- 保留所选风格的构图、信息架构、模块密度、卡片语言、配色、光照、渲染方式和负面约束。
- 用已确认的业务板块和数据重点替换示例业务内容，但不因换行业而删空左右模块或底部明细。
- 用户参考图存在时，先提取其布局、配色、材质和视觉层级，再用内置提示词的完整性规则补足信息架构；不得让内置风格覆盖参考图的核心特征。
- 同一轮候选保持业务主题、指标和 viewport 一致，主要改变风格、构图或信息组织。

参考图只用于确认视觉方向和信息密度。正式页面中的标题、图表、表格和数据仍通过 HTML/CSS 与可视化组件重建。

## 4K 图片发布优化

现有 8 张 PNG 均为 3840×2160，总体积约 65 MB。发布版本改为相同分辨率的 WebP：

1. 使用 `cwebp` 移除元数据并编码为有损 WebP，初始质量采用 84、method 6。
2. 不降低 3840×2160 分辨率，避免破坏细线、渐变、玻璃层次和局部材质判断。
3. 目标总体积为 12–16 MB。若超出目标，从体积最大的图片开始逐级降低质量，但不低于 80。
4. 如果某张图片出现影响风格选择的渐变断层、文字块化、边缘光晕、细线丢失或材质糊化，单独提高该图质量；视觉可选性优先于体积目标。
5. 更新 Markdown 中的 8 个 4K 图片链接，确认仓库内没有旧路径引用后移除原 PNG。
6. 删除资源目录内的 `.DS_Store`，避免无关文件进入发布包。

视觉验收同时检查适配窗口预览和 100% 局部细节。自动检查覆盖文件数量、WebP 格式、3840×2160 尺寸、旧 PNG 引用和总体积；人工检查覆盖布局、主色、信息密度、文字层级以及玻璃、发光、PBR 和自然纹理等关键质感。

## 失败处理

- 风格资料或参考图缺失时，不静默回退到 `DESIGN.md`；应说明缺失资源并停止候选图生成。
- 用户参考图与文字要求冲突时，指出冲突并让用户确认优先项。
- 3 套推荐无法形成实质差异时，优先拉开中央载体、卡片语言、数据密度和光照方式，而不是减少业务模块。
- WebP 压缩未达到体积目标但继续压缩会影响风格判断时，保留较高质量并报告实际体积。

## 验收标准

- 数据驾驶舱 Skill 明确跳过默认 `DESIGN.md` 流程，且不会影响其他原型 Skill。
- 没有设计输入时，用户会先看到 3 套带参考图、布局、主题色和取舍的内置风格推荐。
- 用户参考图和明确要求的优先级高于内置风格。
- 候选图提示词继承完整视觉结构与负面约束，不退化为简短风格标签。
- 8 张发布参考图保持 3840×2160，风格判断不受压缩影响，发布体积显著低于当前约 65 MB。
- 旧 4K PNG 不再被 Markdown 或 Skill 引用，资源目录不包含 `.DS_Store`。
- `.agents` 与 `.claude` Skill 镜像一致，相关 Vitest 全部通过。
