# 统一 PRD 模板设计

## 背景

Make Client 当前内置轻量 PRD 与完善型 PRD 两个模板。两者共用同一套规划和编写流程，但 `plan-prds` 需要额外确认模板，`write-prd`、模板清单和测试也需要同时维护两个入口。

本次将两个内置模板收敛为一个，降低选择和维护复杂度。

## 方案比较

1. 继续保留两个模板：使用方式不变，无法达到降低复杂度的目标。
2. 只保留现有完善型模板并要求完整填写：入口最少，但简单需求的文档负担偏高。
3. 保留一个可伸缩模板：未标记章节默认保留，仅将按需内容标记为“（可选）”。该方案兼顾单一入口与不同规模需求，采用此方案。

## 统一模板

唯一内置入口保持为 `src/resources/templates/prd-template.md`。模板标题使用“PRD 模板”，不再区分轻量型或完善型。

模板只保留一条使用说明：标题标有“（可选）”的章节按需使用，其余章节默认保留。

### 默认保留章节

- 背景与问题
- 目标与成功标准
- 用户、角色与场景
- 范围
- 用户故事
- 业务规则
- 状态、异常与边界
- 字段、内容与交互要求
- 验收标准与来源追溯
- 开放问题

### 可选章节

- 文档目录与关联文档（可选）
- 能力与信息架构（可选）
- 数据模型（可选）
- 权限与作用范围（可选）
- 非功能要求（可选）
- 风险与依赖（可选）

## 流程调整

- `plan-prds` 不再展示轻量型与完善型选项，也不再要求用户确认内置模板；未指定模板时直接记录统一模板。
- 用户明确提供自定义模板时仍然允许覆盖计划或单个 PRD 任务。
- `write-prd` 默认读取统一模板，并继续接受上游传入的自定义模板路径。
- 删除 `prd-comprehensive-template.md`，并从客户端模板清单中移除。
- 同步 `.agents` 与 `.claude` 下的镜像技能，保持内容一致。

## 兼容边界

已有 PRD 文档不迁移、不改写。统一只影响后续规划和编写。旧模板路径不增加别名或兼容入口；若已有任务显式记录了被删除的模板路径，应在执行前改为统一模板或用户指定的自定义模板。

## 验证

- 更新模板测试，确认唯一内置模板包含全部默认章节和带“（可选）”标识的可选章节。
- 确认 `plan-prds` 不再包含两个内置模板的选择步骤，并保留自定义模板覆盖能力。
- 确认 `write-prd` 默认指向 `src/resources/templates/prd-template.md`。
- 确认客户端模板清单不再引用 `prd-comprehensive-template.md`。
- 确认 `.agents` 与 `.claude` 的对应技能文件一致。
