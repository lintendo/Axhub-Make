# 来源处理与命名

只读取当前任务实际出现的来源。先在所选产品目录的 `SOURCES.md` 登记，再按下表采集；长期产物放入该目录的 `sources/`。

## 处理表

| 来源 | 处理方式 | 必须登记的产物 |
| --- | --- | --- |
| 网站链接 | 使用可用的 Browser、Playwright 或浏览器自动化能力，先枚举导航和进入路径，尽量覆盖当前访问条件下可进入的全部页面与关键状态；需要登录时优先使用 Chrome CDP 或 Bridge 复用用户登录状态，不索取或持久化用户密码 | 访问条件、页面架构、路由/进入路径、截图、关键交互、覆盖边界和未覆盖区域 |
| 截图和图片 | 使用图像读取能力分析；保留原图或引用稳定原路径 | 图片文件、可观察内容、关联页面和来源编号 |
| PDF、DOCX、PPTX、表格 | 使用运行环境内置的对应文档能力；需要时保存结构化提取文本 | 原文件、提取结果、章节/工作表范围 |
| Axure | 使用 `extract-axure-data`：`https://github.com/lintendo/Axhub-Skills/tree/main/skills/extract-axure-data` | 页面、截图、交互、标注和结构化结果 |
| 飞书文档和多维表格 | 使用 `https://www.skills.sh/larksuite/cli`；需要授权时请用户完成授权 | 原始链接、文档内容、字段、表格范围和授权缺口 |
| 其他在线文档 | 使用能保留原始结构、章节和引用关系的读取方式 | 原始链接、提取文本、章节索引 |
| 互联网调研 | 只处理用户已授权的新增或创作需求；按“搜索引擎检索 -> 客户证据研究”执行，第二步使用 `china-customer-research`：`https://github.com/lintendo/Axhub-Skills/blob/main/skills/china-customer-research/SKILL.md` | 检索词、候选与原始 URL、访问日期、市场范围、证据与置信度、结论用途、外部研究标记 |

## 网站采集

1. 先列导航、页面入口和可见角色范围，再决定采集顺序。
2. 每个页面记录默认、空、错误、权限、弹窗、抽屉或关键操作状态；只采集实际可进入的状态。
3. 截图与页面表逐项对应，不能只保存图片而不写页面关系。
4. 无限列表、动态数据和权限不可见区域写明采集边界，不能声称“全部完成”。
5. 回归时按 `SOURCES.md` 找原路径和状态，新增版本保留原来源编号。

主采集完成条件：已枚举当前可进入的全部页面/入口，完成默认状态和当前可进入的关键交互；未展开的弹窗、抽屉、错误和权限状态登记为补采项，不得将来源标为 `已完成`。

## 文件命名

只使用小写字母、数字和连字符表达英文语义；控制文档名保持固定大写。

| 对象 | 格式 | 示例 |
| --- | --- | --- |
| 来源编号 | `src-<三位序号>` | `src-003` |
| 模块 PRD | `prd-<两位序号>-<module-id>.md` | `prd-02-inventory-transfer.md` |
| 网站截图 | `<三位序号>-<page-id>-<state-id>-<viewport>.png` | `020-login-error-desktop.png` |
| 图片资料 | `<三位序号>-<subject>.<ext>` | `010-order-flow.png` |
| 文档资料 | `<三位序号>-<semantic-name>.<ext>` | `030-business-rules.pdf` |
| 文档提取结果 | `<原文件名去扩展名>.extracted.md` | `030-business-rules.extracted.md` |

同一来源更新时保留编号。时间戳和随机字符串不能作为主要名称；确实保留多次采集时，在语义名称后增加版本或日期。

## 失败与冲突

- 资源无效、无法访问、无法读取或解析、存在权限或授权限制：在 `SOURCES.md` 标为 `阻塞`，写清原因、影响和后续处理，继续采集其他可执行项，最后由主流程汇总。
- 用户说明与页面事实冲突：两项都保留，在“来源缺口与冲突”表记录，来源标为 `阻塞`，证据属性标为 `待用户确认`。
- 多个来源结论不一致：逐项引用，来源标为 `阻塞`，证据属性标为 `待用户确认`，不自行选择有利版本。
- 现状反推缺少证据：仍有可采集证据时保持 `部分完成` 并继续；穷尽可执行采集后仍缺证据才标为 `阻塞`，不用互联网研究或行业惯例补写当前能力。
