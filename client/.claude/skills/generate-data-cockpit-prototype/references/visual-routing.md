# 大屏视觉与技术路由

选图后只从图片事实中提取常用视觉元素。选中图片决定可见结果，技术实现负责在不改变该结果的前提下恢复真实文本、数据、交互和空间能力。

## 常用视觉元素

| 类别 | 常见内容 | 默认实现与边界 |
| --- | --- | --- |
| 场景基底 | 背景色、渐变、空间环境、地貌、底纹、环境光 | CSS/SVG/分层图片；不合并标题、图表、控件和业务文字 |
| 中央主视觉 | GIS 地图、数字沙盘、数字孪生、3D 模型、拓扑或核心分析区域 | 按交互需要使用地图、ECharts、Three.js 或真实模型；只有确认无需空间交互时才使用图片 |
| UI 框架 | 主标题、模块标题、面板、图表、指标、表格与主视觉的框架和底板 | 优先复用共享 CSS/SVG 框架组件；复杂无状态纹理可使用透明图片 |
| 数据内容 | 标题、KPI、图表、表格、列表、筛选器、标签和按钮 | 使用 HTML/CSS/React 与 ECharts 保留真实文本、数据和交互，不把图表烘焙为图片 |
| 标注与状态 | 地图 Marker、对象标签、告警、状态灯、路线、数据流和连接关系 | 使用 DOM/SVG、图表层、地图层或 3D 场景对象，保持状态语义和联动 |
| 装饰与特效 | 网格、刻度、扫描线、粒子、光晕、云雾、纹理和不可交互光效 | CSS/SVG/图片/着色器；不得承载内容分区或真实数据 |
| 图标与媒体 | Logo、业务图标、徽标、设备图片、视频、监控和图片墙 | 使用项目图标库、SVG 或媒体组件，明确比例、播放、加载和异常状态 |

## UI 框架

框架承担信息分区、层级或内容承载；仅营造氛围的粒子、光效、扫描线和纹理属于装饰与特效。

- **大屏主标题框架**：顶部主标题、标题底座及两侧延伸结构。
- **模块标题框架**：业务模块标题栏、页签承载区和标题角标。
- **面板框架**：左右业务模块、底部模块和浮动卡片的外框或底板。
- **图表框架**：折线图、柱状图、环形图等图表的外围容器；图表框架不包含真实图表、图例、坐标或数据文字。
- **指标框架**：KPI、大数字、仪表和状态指标的承载区。
- **表格与列表框架**：告警、排行、事件和运行明细的外层结构。
- **主视觉框架**：包围或承托地图、沙盘、模型和拓扑的底座、扫描环或视觉边界。

同类框架复用一套组件和状态变量。优先用 CSS/SVG 重建可缩放结构；必须使用透明图片时，记录九宫格拉伸区、不可拉伸细节、内容安全区和默认/高亮/告警状态。框架素材不得包含真实标题、图表、KPI 数字、表格内容或交互控件。

## 地图路由

先判断地图表达的是“行政区域造型”还是“真实地理底图”。

- 行政区、省市县轮廓、科技感挤出和区域飞线：使用合法 GeoJSON 配合 ECharts 或 Three.js。需要明显的 3D 厚度、材质、灯光和空间交互时使用 Three.js。
- 园区、厂区、建筑群的真实空间：优先使用 GIS/BIM/GLTF 数据；按缩放层级和交互深度选择 Three.js、AntV L7 或 deck.gl。
- 街道、卫星、道路和真实 POI 全场景底图：国内项目通常使用高德地图并叠加 AntV L7；可控或离线样式使用 MapLibre；大规模空间数据可使用 deck.gl。Mapbox 仅在项目已有授权和 Token 时采用。
- 在规格中记录坐标系、数据范围、底图供应商、Token/授权、离线要求、聚合方式与降级状态，不伪造可用底图服务。

## 3D 主 VI 路由

主 VI 不限行业：可为工厂、电站、设备、园区、楼宇、城市、港口、机场、仓库、矿区、油气装置、流域、水利设施、交通枢纽、机房、卫星、飞行器、农场、景区或其他承担空间关系的对象。

满足任一条件时优先真实 3D：需要旋转/缩放/点选，需要表达内部结构或空间关系，需要设备状态映射，需要镜头漫游，或选中图片明确呈现具有体积和视角关系的主体。

只按最终能力选择实现路线：

1. 需要真实空间交互、内部结构或状态映射时，交付可运行的 GLTF/GLB、BIM、CAD 或 GIS 产物，并完成格式转换、减面、贴图和坐标校准。
2. 规则结构可用程序化几何实现；需要建模且环境中的 `img2threejs` 等能力可用时直接生成运行产物，不可用时使用正面、侧面、背面、俯视等多角度参考图完成建模。
3. 只有用户确认主 VI 无需真实空间交互时，才可使用透明图片或背景合成。

规格只记录最终运行产物路径、格式、坐标、优化要求和交互能力，不记录其获取或生成来源。

需要真实 3D 时采用 Three.js；React 18.2.0 项目使用 `@react-three/fiber@8`。Three.js/R3F 负责场景、相机、灯光、材质、后处理、拾取、模型状态和性能预算。规格要求的 3D 不得降级为背景图；确需降级必须说明损失并等待用户确认。

## 动画路由

- CSS 动画：微光、呼吸、边框流光、简单过渡。
- ECharts：图表入场、更新、强调和轮播。
- Three.js/R3F：相机、模型、粒子、材质与空间时间轴。
- 地图库：视角飞行、图层更新和空间轨迹。
- GSAP 不是默认依赖。仅当一个时间线需要统一编排 DOM、ECharts、地图和 Three.js，或需要可暂停/回放的复杂叙事时使用 `gsap`/`@gsap/react`；可参考官方 `greensock/gsap-skills` 作为开发指导。

动画必须支持大屏稳定运行：限制同时动画数量、粒子和后处理成本，处理页面不可见状态，并尊重降动效设置。

规格必须依据目标硬件与真实数据量明确预算：viewport、DPR、目标帧率、模型面数/纹理、点位和轨迹规模、刷新频率、首次加载/数据更新时的动画生命周期，以及各渲染引擎的 ready/超时策略。不要用脱离项目的统一阈值替代测量。
