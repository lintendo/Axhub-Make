# 数据大屏设计对齐

## 权威资料

`../../../../src/resources/data-visualization-style-reference/visualization-style-prompts.md` 是内置 8 套风格、参考图和完整提示词的唯一来源；不要在本 Skill 复制完整提示词。为节省上下文，禁止一次性读取全文：文字方案阶段只读取“风格总览”及候选风格标题下、`### 完整提示词` 之前的简介和参考图；用户确认后只读取已确认风格的“完整提示词”段落。

八套风格只用于候选图提示词和视觉方向参考。图片冻结后以选中图片为唯一视觉事实，后续还原不再按风格案例分类素材，而是按通用视觉元素拆分和实现。

## 输入优先级

按以下顺序处理设计输入：

1. 用户参考图。
2. 用户明确的布局、风格和主题色。
3. 内置 8 套风格。

用户要求与内置风格冲突时，以用户最新明确要求为准。参考图存在时，先提取它的构图、配色、材质和视觉层级，再用内置资料补足未说明的信息架构，不得覆盖参考图的核心特征。

如果用户提供的是需要直接还原的完整目标大屏截图，而不是用于启发新方案的参考图，返回主流程跳过候选图生成，将该图直接冻结为选中图片。

## 对齐内容

只对齐会影响候选图的设计决策：

- 业务板块、核心指标和信息优先级。
- 顶部、左右、中部和底部的主要板块与布局。
- 中央载体采用 GIS、2.5D、3D、拓扑还是纯 BI。
- 设计风格、明暗倾向和信息密度。
- 主色、辅助色、状态色和告警色组成的主题色。
- 参考图中需要继承的构图、配色、材质或氛围。

## 无设计输入时

根据行业匹配度、数据密度、GIS/3D 倾向、明暗倾向和文化气质，从权威资料中推荐 3 套有实质差异的方向。不要只改变颜色而保留相同构图。

每套方向包含：

- 风格名称和参考图；必须原样嵌入权威资料中的 Markdown 参考图链接，不得只写文件名或文字说明。
- 推荐理由。
- 主要板块与布局。
- 中央载体。
- 主题色。
- 主要取舍。

先展示 3 套文字方案和对应参考图，不展开未选方案的完整提示词。展示后停止；确认前禁止生成图片、调用图片接口或创建提示词文件。用户确认一个或多个方向，或确认合并方案后，才为已确认方向组装完整提示词并生成图片。

用户已经明确指定单一参考图、布局、风格或主题色方向，或明确只要一套方案时，用一套文字方案复述最终板块、布局、中央载体和视觉方向并等待确认，不能把代理内部构思视为用户确认。用户只是提供零散约束、没有指定单一方向或数量时，仍默认提供 3 套。

## 提示词合同

用户确认文字方案后，以所选风格的完整提示词为骨架：

1. 替换行业、标题、中央载体、核心业务对象和关键指标。
2. 保留构图、信息架构、模块密度、卡片语言、配色、光照、渲染方式和负面约束。
3. 用已确认的业务板块替换示例业务内容，不因换行业而删空左右模块或底部明细。
4. 用户要求优先；不得只摘取风格名称或少量关键词。
5. 同一轮候选保持业务主题、指标和 viewport 一致，主要改变风格、构图或信息组织。

参考图只用于确认视觉方向和信息密度。正式页面中的标题、图表、表格和数据仍使用 HTML/CSS 与可视化组件重建。

## 失败处理

- 权威资料或参考图缺失时，说明问题并停止生成，不静默回退到 `DESIGN.md`。
- 用户参考图与文字要求冲突时，指出冲突并确认优先项。
- 3 套方向趋同时，拉开中央载体、卡片语言、数据密度和光照方式，不减少业务模块来制造差异。
