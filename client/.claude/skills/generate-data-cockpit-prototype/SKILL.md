# 生成数据驾驶舱原型

先生成候选大屏图；用户选图后，以该图为唯一视觉标准，依次完成 HTML 规格、React 实现和同视口验收。

## 使用边界

- 完整流程使用本 Skill。
- 用户只要候选效果图时，直接使用 `ui-image-generation`。
- 用户已经提供本地截图且只要还原时，直接使用 `screenshot-to-prototype`。
- 开始前读取最近的 `AGENTS.md`、`../../../rules/requirements-alignment-guide.md` 和 `../../../rules/prototype-development-guide.md`；已有项目还要读取现有规格。

## 强制阶段门禁

### 1. 临时对齐需求

按 `rules/requirements-alignment-guide.md` 对齐目标角色、核心任务、展示环境、数据重点、行业语义、视觉气质、地图和 3D 倾向。需要行业提示时读取 [industry-scenes.md](references/industry-scenes.md)。

- 需求对齐只用于生成图片提示词。
- 本 Skill 是 client 默认设计对齐流程的明确例外：仍读取需求对齐指南，但跳过 `DESIGN.md` 候选、主题深链和设计基底确认，不新建 `DESIGN.md`，也不复用其中的 tokens。
- 按 [style-alignment.md](references/style-alignment.md) 对齐业务板块、整体布局、中央载体、设计风格和主题色。
- 设计输入按“用户参考图 → 用户明确的布局、风格和主题色 → 内置 8 套风格”处理。没有任何设计输入时，推荐 3 套有实质差异的内置风格并分别用于候选图；不静默回退到 `DESIGN.md`。
- 前期设计选择只影响候选图提示，选图后不得用于纠正选中图片。
- 图片确认前不创建或更新主规格，也不把对齐结果同步到已有规格。
- 图片确认前不创建需求 Brief、PRD、素材清单或其他中间需求文档。
- 在对话中只保留生成候选图所需的信息，不要求把场景字段逐项记录完整。

### 2. 生成候选图片

读取并遵循 `../ui-image-generation/SKILL.md`；同时使用 `../explore-options/SKILL.md` 让候选方案在构图、主 VI 或信息组织上有实质差异。

- 图片数量由用户指定数量；没有指定时默认 3 张。
- 所有候选保持相同目标 viewport 和业务主题，每张图单独生成并检查。
- 候选图允许偏离早期设想。此阶段不提前承诺最终技术栈，也不写入主规格。
- 展示全部候选图，说明核心差异，等待用户选择。
- 用户要合并多个方案时，先生成一张合并后的新图，再等待明确选择。

### 3. 冻结选中图片

只有用户明确选中图片后才能进入还原阶段：

1. 将最终图片复制到目标原型的 `.spec/reference/selected-source.png`，记录尺寸和 SHA-256。
2. 选中图片是所有可见视觉事实的唯一还原标准；不使用前期需求纠正选中图片。
3. 选图后才整理图片无法表达且仍有效的非视觉运行约束，例如数据源/时效、地图服务、真实 3D、交互、动画、性能和权限；冲突或不确定项先请用户确认，再交给规格子代理写入主规格，不另建 Brief。
4. 用户最新明确修改优先于图片，并同步到后续规格；明显视觉改向时重新冻结参考图。

### 4. 由规格子代理创建主规格

按 [subagent-handoffs.md](references/subagent-handoffs.md) 启动干净的规格子代理，创建或更新 HTML 主规格 `.spec/spec.html`。

规格至少覆盖：同视口视觉稿、区域结构、真实文本、素材对照表、图表/地图/3D/动画路由、交互状态与验收口径。不得把真实图表或交互控件切成位图。

规格完成后，提供完整 Make 服务规格评审链接并结束当前回合，等待用户评审；不要继续写 React。

### 5. 由实现子代理制作 React 原型

用户明确确认当前 HTML 主规格后，才进入 React 实现。使用与规格子代理不同的干净子代理，并只传入选中图片、确认后的规格、项目上下文和必要规则。

- 严格实现已确认规格；使用 [visual-routing.md](references/visual-routing.md) 选择图表、地图、3D 和动画方案。
- 规格不清楚或实现需要可见降级时，回到规格阶段等待用户确认。
- 实现完成后同步主规格中的实现状态与必要偏差，不回填早期对齐内容。

### 6. 由验收子代理独立检查

使用第三个干净的验收子代理，在相同 viewport 下对比选中图片、HTML 主规格渲染和 React 运行页。按 `screenshot-to-prototype` 的验收规则检查视觉、功能、控制台、溢出与资源完整性，问题回交相应阶段修复。

## 子代理不可用

若环境没有子代理，明确告知上下文隔离不可用，并在“选图 → 规格”“规格确认 → 实现”“实现 → 验收”的阶段门建议新开对话。未经用户同意，不在混杂上下文中静默跨阶段。
